## 1. 변경할 수 없는 리스트

### 1.1 메서드 비교

| 메서드 | 추가/삭제 | 수정 | `null` | 원본이 바뀌면 | 용도 |
| --- | --- | --- | --- | --- | --- |
| `List.of(...)` | ❌ | ❌ | ❌ | 영향 없음 | 새로 만들기 |
| `List.copyOf(list)` | ❌ | ❌ | ❌ | 영향 없음 | 기존 리스트 고정 |
| `Collections.unmodifiableList(list)` | ❌ | ❌ | ✅ | 같이 바뀜 | 읽기 전용 뷰 |
| `Arrays.asList(...)` | ❌ | ✅ | ✅ | 같이 바뀜 | 크기만 고정 |

**완전히 변경할 수 없는 것은 `List.of()`, `List.copyOf()`뿐이다.**

```java
List<String> view = Collections.unmodifiableList(source);
List<String> copy = List.copyOf(source);

source.add("b");    // view는 바뀌고, copy는 그대로
```

### 1.2 List.of() 주의사항

| 상황 | 결과 |
| --- | --- |
| `add()`, `set()`, `remove()` 호출 | `UnsupportedOperationException` (실행 중 발생) |
| `List.of("a", null)`처럼 `null`을 넣을 때 | `NullPointerException` |
| `contains(null)` 호출 | `NullPointerException` |
| 원소 객체의 내부 상태 변경 | 막지 못함 |
| 수정이 필요할 때 | `new ArrayList<>(list)`로 복사 |

### 1.3 List.of() 타입 추론

타입이 다른 값을 섞으면 **공통 상위 타입**으로 정해진다.

| 코드 | 받는 타입 |
| --- | --- |
| `List.of(1, 2.0)` | `List<Number>` |
| `List.of(1, "a")` | `List<Object>` |
| `List.of(new Dog(), new Cat())` | `List<Animal>` (`Dog`, `Cat`이 `Animal`을 상속할 때) |

| 주의 | 예시 |
| --- | --- |
| 공통 상위 타입이 아닌 타입으로는 받을 수 없다 | `List<Integer> x = List.of(1, 2.0)` <br/> → 컴파일 에러 |
| 타입이 섞이면 `var` 대신 타입을 직접 적는다 | `var x = List.of(1, 2.0)` <br/> → `x`는 `List<Number>`가 아니라 `List<Number & Comparable<...>>` |
| `List<Object>`가 되는 조합은 피한다 | 꺼낼 때마다 형변환이 필요하다 |
