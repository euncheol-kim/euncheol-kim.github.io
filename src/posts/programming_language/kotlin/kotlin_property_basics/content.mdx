### 🌱 포스팅 작성 이유

Kotlin을 처음 배우면서 프로퍼티 관련 설명을 읽을 때마다 "접근자", "기본 접근자", "초기화 식" 같은 용어가 당연한 듯이 등장했습니다.

이 용어들이 정확히 무엇을 가리키는지 모르면 그 뒤의 설명을 따라갈 수 없었기 때문에, 프로퍼티를 이루는 기본 요소를 먼저 정리합니다.

---

## 1. 프로퍼티란

Java에서는 값을 저장하는 **필드**와 그 값을 읽고 쓰는 **getter/setter 메서드**를 따로 작성합니다.

```java
public class Person {
    private String name;                        // 필드

    public String getName() { return name; }    // getter
    public void setName(String v) { name = v; } // setter
}
```

Kotlin은 이 셋을 **프로퍼티(Property)** 하나로 묶어서 선언합니다.

```kotlin
class Person {
    var name: String = ""
}
```

이 한 줄로 필드, getter, setter가 모두 만들어집니다. `person.name`이라고 읽으면 getter가, `person.name = "Kim"`이라고 쓰면 setter가 호출됩니다. 겉으로는 변수처럼 보이지만 실제로는 메서드 호출입니다.

### 1.1 val과 var

| 키워드 | 의미 | 생성되는 접근자 |
| --- | --- | --- |
| `val` | 읽기 전용 (재할당 불가) | getter만 |
| `var` | 읽기/쓰기 가능 | getter와 setter |

`val`은 setter가 없으므로 선언 이후에 값을 다시 할당할 수 없습니다.

## 2. 접근자(Accessor)

프로퍼티의 값을 읽는 함수가 **getter**, 쓰는 함수가 **setter**이고, 이 둘을 합쳐 **접근자(Accessor)** 라고 부릅니다.

접근자는 직접 쓰지 않아도 자동으로 생기며, 필요하면 직접 정의할 수도 있습니다. 전자를 기본 접근자, 후자를 커스텀 접근자라고 합니다.

### 2.1 기본 접근자

접근자를 직접 쓰지 않으면 컴파일러가 자동으로 만들어 주는 getter/setter입니다. 아래 두 코드는 완전히 같은 의미입니다.

```kotlin
// 접근자를 쓰지 않은 선언
class Person {
    var name: String = ""
}

// 컴파일러가 속으로 만들어 두는 것을 풀어 쓴 모습
class Person {
    var name: String = ""
        get() = field          // 기본 getter : 저장된 값을 그대로 돌려준다
        set(value) {           // 기본 setter : 받은 값을 그대로 저장한다
            field = value
        }
}
```

기본 접근자가 하는 일은 "저장된 값을 그대로 읽기/쓰기"뿐입니다.

### 2.2 커스텀 접근자

`get()`이나 `set(value)`를 직접 작성한 접근자입니다. 검증, 계산, 로깅 등 원하는 동작을 넣을 수 있습니다.

```kotlin
class Person {
    var age: Int = 0
        set(value) {
            require(value >= 0) { "나이는 음수일 수 없습니다." }
            field = value
        }

    val isAdult: Boolean
        get() = age >= 19
}
```

- `age`의 setter는 값을 검증한 뒤 저장합니다.
- `isAdult`의 getter는 저장된 값 없이 `age`로부터 계산해서 돌려줍니다.

커스텀 접근자는 프로퍼티 선언 바로 아래에 들여쓰기해서 작성합니다.

### 2.3 `field` 식별자

커스텀 접근자 안에서만 쓸 수 있는 특별한 이름입니다. **이 프로퍼티의 값이 실제로 저장되는 공간**을 가리킵니다.

접근자 안에서 `field` 대신 프로퍼티 이름을 쓰면 접근자가 자기 자신을 다시 호출해서 무한 재귀가 발생합니다.

```kotlin
var age: Int = 0
    get() = age        // ❌ getter 안에서 getter를 호출 → StackOverflowError

var age: Int = 0
    get() = field      // ✅ 저장 공간에 직접 접근
```

## 3. 초기화 식(Initializer)

프로퍼티를 선언할 때 `=` 뒤에 붙이는 **초기값을 정하는 부분**입니다.

```kotlin
var birthYear: Int = 1995
//                 ^^^^^^ 초기화 식
var ageIn2050: Int = 2050 - birthYear
//                 ^^^^^^^^^^^^^^^^^^ 이것도 초기화 식 (계산식이어도 된다)
```

"식(expression)"이라고 부르는 이유는 `1995` 같은 상수뿐 아니라 `2050 - birthYear`, `listOf()`, `compute()`처럼 **값을 만들어 내는 표현이면 무엇이든** 올 수 있기 때문입니다.

초기화 식은 객체가 생성되는 순간에 **한 번** 평가되고, 그 결과가 프로퍼티의 저장 공간에 들어갑니다. Java로 보면 생성자 안의 대입문 한 줄에 해당합니다.

```java
public Person(int birthYear) {
    this.birthYear = birthYear;
    this.ageIn2050 = 2050 - birthYear;   // 초기화 식이 여기로 옮겨진다
}
```

### 3.1 혼동하기 쉬운 것들

모양이 비슷하지만 실행 시점이 다릅니다.

| 코드 | 이름 | 실행 시점 |
| --- | --- | --- |
| `var a: Int = 1995` | 초기화 식 | 객체 생성 시 한 번 |
| `class P(var a: Int = 1995)` | 생성자 파라미터 기본값 | 인자를 생략하고 호출할 때 |
| `init { ... }` | 초기화 블록 | 객체 생성 시 한 번 (여러 줄 가능) |
| `get() = 2050 - birthYear` | 커스텀 getter | 프로퍼티를 읽을 때마다 |

특히 초기화 식과 커스텀 getter는 둘 다 `=` 뒤에 식이 오기 때문에 헷갈리기 쉽습니다. 초기화 식은 생성 시 한 번 계산해서 **저장**하고, getter는 읽을 때마다 **다시 계산**합니다.

```kotlin
class Person(var birthYear: Int) {
    val a: Int = 2050 - birthYear       // 생성 시 한 번 계산, 이후 birthYear가 바뀌어도 그대로
    val b: Int get() = 2050 - birthYear // 읽을 때마다 계산, birthYear가 바뀌면 같이 바뀜
}
```

## 4. Backing Field

프로퍼티의 값이 실제로 저장되는 공간을 **Backing Field(뒷받침하는 필드)** 라고 합니다. 접근자 안에서 `field`로 접근하는 바로 그 공간입니다.

중요한 점은 **모든 프로퍼티에 Backing Field가 있는 것은 아니라는 것**입니다. 2.2의 `isAdult`처럼 getter가 다른 값으로부터 계산만 하고 `field`를 쓰지 않으면, 저장할 것이 없으므로 컴파일러는 Backing Field를 만들지 않습니다.

언제 생기고 언제 생기지 않는지, 없을 때 무엇이 달라지는지는 다음 글에서 다룹니다.

## 5. 정리

| 용어 | 뜻 |
| --- | --- |
| 프로퍼티 | 필드 + getter + setter를 하나로 묶은 선언 |
| 접근자 | getter와 setter를 통칭하는 말 |
| 기본 접근자 | 직접 쓰지 않아서 컴파일러가 만들어 준 접근자. 저장된 값을 그대로 읽고 쓴다 |
| 커스텀 접근자 | `get()` / `set(value)`를 직접 작성한 접근자 |
| `field` | 커스텀 접근자 안에서 자기 프로퍼티의 저장 공간을 가리키는 식별자 |
| 초기화 식 | 선언 시 `=` 뒤에 오는 식. 객체 생성 시 한 번 평가되어 저장된다 |
| Backing Field | 프로퍼티 값이 실제로 저장되는 공간. 필요할 때만 생성된다 |
