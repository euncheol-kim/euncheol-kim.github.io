### 🌱 포스팅 작성 이유

`Delegates.observable()`의 `Delegates`는 클래스가 아니라 `object`였습니다. 객체를 만든 적이 없는데 `Delegates.observable()`처럼 이름에 바로 점을 찍어 쓸 수 있었던 이유가 여기에 있습니다.

`object` 키워드가 쓰이는 세 가지 자리와 각각의 의미를 정리합니다.

---

## 1. object는 "선언과 동시에 생성"이다

`class`는 설계도입니다. 선언만으로는 객체가 생기지 않고, 생성자를 호출해야 객체가 만들어집니다.

```kotlin
class Counter          // 설계도만 있다
val counter = Counter()    // 이때 객체가 생긴다
```

`object`는 **설계도를 그리면서 그 설계도로 만든 객체까지 함께 만듭니다.**

```kotlin
object Counter         // 설계도와 객체가 함께 생긴다
```

이 한 가지 성질이 쓰이는 자리에 따라 세 가지 모습으로 나타납니다.

| 종류 | 형태 | 용도 |
| --- | --- | --- |
| object 선언 | `object Counter { }` | 프로그램 전체에서 하나뿐인 객체(싱글톤) |
| companion object | `class User { companion object { } }` | 클래스에 딸린 하나뿐인 객체. Java의 `static` 자리 |
| object 식 | `object : Listener { }` | 이름 없는 객체를 그 자리에서 만들기 |

---

## 2. object 선언: 하나뿐인 객체

### 2.1 싱글톤

프로그램 전체에서 객체가 단 하나만 존재하도록 하는 것을 **싱글톤(Singleton)** 이라고 합니다. Java에서는 이를 위해 정해진 코드를 직접 작성해야 합니다.

```java
public class Counter {
    private static final Counter INSTANCE = new Counter();
    private Counter() {}                                   // 밖에서 new 하지 못하게 막는다
    public static Counter getInstance() { return INSTANCE; }

    private int count = 0;
    public void increase() { count++; }
}
```

Kotlin은 `object` 한 단어로 끝납니다.

```kotlin
object Counter {
    var count = 0
    fun increase() { count++ }
}
```

### 2.2 사용

객체가 이미 만들어져 있으므로 **이름에 바로 점을 찍어** 씁니다.

```kotlin
Counter.increase()
Counter.increase()

println(Counter.count)    // 2
```

생성자를 호출할 수 없습니다. 객체가 하나뿐이어야 하기 때문입니다.

```kotlin
val counter = Counter()    // ❌ 컴파일 에러
```

`Counter`라는 이름은 클래스 이름이면서 동시에 그 하나뿐인 객체를 가리킵니다. 변수에 담아도 같은 객체입니다.

```kotlin
val a = Counter
val b = Counter

println(a === b)    // true
```

### 2.3 특징

| 특징 | 설명 |
| --- | --- |
| 생성자 파라미터를 가질 수 없다 | 직접 생성하는 것이 아니므로 값을 넘겨줄 곳이 없다 |
| 처음 사용할 때 만들어진다 | 프로그램 시작 시점이 아니라 `Counter`에 처음 접근하는 순간 초기화된다 |
| 인터페이스를 구현할 수 있다 | 일반 클래스처럼 상속과 구현이 된다 |

```kotlin
interface Logger {
    fun log(message: String)
}

object ConsoleLogger : Logger {
    override fun log(message: String) = println("[LOG] $message")
}

ConsoleLogger.log("시작")    // [LOG] 시작
```

`Logger`가 필요한 자리에 `ConsoleLogger`를 그대로 넘길 수 있습니다.

### 2.4 주의: 상태를 가진 object는 전역 변수다

`object`는 어디서든 접근할 수 있으므로, 앞의 `Counter`처럼 `var`를 가지면 프로그램 전체가 공유하는 가변 상태가 됩니다. 누가 언제 값을 바꿨는지 추적하기 어려워집니다. ([불변 객체 글](/blog/programming_concept/immutable_object)의 "공유된 가변 상태" 참고)

`object`는 상태가 없는 기능 모음(`Delegates` 등)이나 변하지 않는 값을 담는 용도로 쓰는 것이 안전합니다.

## 3. companion object: 클래스에 딸린 객체

### 3.1 Kotlin에는 static이 없다

Java에서는 객체를 만들지 않고 클래스 이름으로 바로 부르는 멤버를 `static`으로 만듭니다. Kotlin에는 `static` 키워드가 없고, 그 자리를 **클래스 안에 선언한 object**가 대신합니다. 이것이 `companion object`입니다.

```kotlin
class User private constructor(val name: String) {

    companion object {
        const val MAX_NAME_LENGTH = 10

        fun of(name: String): User {
            require(name.length <= MAX_NAME_LENGTH)
            return User(name)
        }
    }
}
```

### 3.2 사용

`companion object` 안의 멤버는 **클래스 이름으로 바로** 부릅니다.

```kotlin
val user = User.of("철수")

println(user.name)               // 철수
println(User.MAX_NAME_LENGTH)    // 10
```

위 예시는 companion object의 대표적인 두 용도를 보여 줍니다.

| 용도 | 예시 | 설명 |
| --- | --- | --- |
| 상수 | `const val MAX_NAME_LENGTH` | 클래스와 관련된 고정 값 |
| 팩토리 메서드 | `fun of(name)` | 생성자를 `private`으로 막고, 검증을 거친 객체만 만들어 내보낸다 |

```kotlin
val user = User("철수")    // ❌ 컴파일 에러: 생성자가 private이다
```

### 3.3 특징

| 특징 | 설명 |
| --- | --- |
| 클래스당 하나만 선언할 수 있다 | |
| 클래스의 `private` 멤버에 접근할 수 있다 | `of()`가 `private` 생성자를 호출할 수 있었던 이유다 |
| 이름을 붙일 수 있다 | `companion object Factory { }`. 생략하면 이름은 `Companion`이 된다 |
| 실제로는 객체다 | `static`과 달리 인터페이스를 구현하거나 변수에 담을 수 있다 |

`User.of("철수")`는 `User.Companion.of("철수")`를 줄여 쓴 것입니다. 겉모습은 Java의 `static` 호출과 같지만, 실제로는 `User` 클래스에 딸린 객체 하나의 메서드를 부르는 것입니다.

## 4. object 식: 이름 없는 객체

### 4.1 그 자리에서 만들어 쓴다

인터페이스를 구현한 객체가 한 번만 필요할 때, 클래스를 따로 선언하지 않고 **필요한 자리에서 바로** 만들 수 있습니다. 이름이 없으므로 익명 객체(Anonymous Object)라고 부릅니다.

```kotlin
interface ClickListener {
    fun onClick()
}

val listener = object : ClickListener {
    override fun onClick() = println("클릭")
}

listener.onClick()    // 클릭
```

`object : ClickListener { ... }`는 "`ClickListener`를 구현한 이름 없는 클래스를 선언하고, 그 객체를 하나 만든다"는 뜻입니다. "선언과 동시에 생성"이라는 `object`의 성질이 그대로 적용됩니다.

함수에 넘길 객체를 그 자리에서 만들 때 자주 씁니다.

```kotlin
val sorted = listOf("bb", "a", "ccc").sortedWith(object : Comparator<String> {
    override fun compare(a: String, b: String) = a.length - b.length
})

println(sorted)    // [a, bb, ccc]
```

### 4.2 object 선언과의 차이

이름이 비슷하지만 object 식은 싱글톤이 **아닙니다.** 식이 실행될 때마다 새 객체가 만들어집니다.

```kotlin
fun makeListener(): ClickListener = object : ClickListener {
    override fun onClick() = println("클릭")
}

val a = makeListener()
val b = makeListener()

println(a === b)    // false
```

| | object 선언 | object 식 |
| --- | --- | --- |
| 이름 | 있다 | 없다 |
| 객체 수 | 하나 | 식이 실행될 때마다 하나씩 |
| 만들어지는 시점 | 처음 사용할 때 | 식이 실행되는 즉시 |
| 쓰는 곳 | 어디서든 이름으로 | 만든 자리에서 |

## 5. data object

`object`를 출력하면 알아보기 어려운 문자열이 나옵니다.

```kotlin
object Loading

println(Loading)    // Loading@1b6d3586
```

앞에 `data`를 붙이면 이름 그대로 출력됩니다. (Kotlin 1.9부터)

```kotlin
data object Loading

println(Loading)    // Loading
```

값이 없는 상태 하나를 나타내는 object에 주로 씁니다. 로그에 찍거나 디버깅할 때 읽기 쉬워집니다.

---

## 6. 마무리

`object`는 **클래스를 선언하면서 그 객체를 함께 만드는** 키워드입니다.

| 쓰는 자리 | 결과 |
| --- | --- |
| 파일이나 클래스 안에 이름과 함께 | 프로그램에 하나뿐인 객체 (object 선언) |
| 클래스 안에 `companion`과 함께 | 클래스 이름으로 접근하는 하나뿐인 객체 (companion object) |
| 식이 필요한 자리에 이름 없이 | 그 자리에서 만들어지는 새 객체 (object 식) |

객체를 만든 적이 없는데 이름에 바로 점을 찍어 쓰는 코드를 보면 `object`나 `companion object`를 떠올리면 됩니다.
