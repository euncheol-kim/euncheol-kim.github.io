### 🌱 포스팅 작성 이유

Kotlin 코드를 읽다 보면 `?.let { }`, `.apply { }`, `.also { }`가 끊임없이 나옵니다. 다섯 개 모두 "객체에 블록을 붙여 실행한다"는 점이 같아서, 무엇을 언제 쓰는지 구분하기 어렵습니다. 다섯 함수를 가르는 기준 두 가지를 먼저 잡고, 그 기준으로 각 함수를 정리합니다.

---

## 1. 스코프 함수란

**스코프 함수(Scope Function)** 는 어떤 객체를 블록 안으로 가져와서, 그 **객체를 대상으로 코드를 실행**하게 해 주는 표준 라이브러리 함수입니다. `let`, `run`, `with`, `apply`, `also` 다섯 가지가 있습니다.

스코프 함수가 없으면 같은 변수 이름을 계속 반복해야 합니다.

```kotlin
val person = Person()
person.name = "Minji"
person.age = 25
```

스코프 함수를 쓰면 블록 안이 `person`을 위한 공간이 되어, 이름을 반복하지 않아도 됩니다.

```kotlin
val person = Person().apply {
    name = "Minji"
    age = 25
}
```

새로운 기능을 더해 주는 것은 아닙니다. 같은 일을 더 짧고 읽기 좋게 쓰도록 돕는 도구입니다.

---

## 2. 다섯 함수를 가르는 두 가지 기준

다섯 함수의 차이는 두 가지 질문으로 모두 설명됩니다.

### 2.1 블록 안에서 객체를 무엇이라고 부르는가

| 부르는 이름 | 특징 | 해당 함수 |
| --- | --- | --- |
| `this` | 생략할 수 있다. 객체의 멤버를 이름만으로 쓴다 | `run`, `with`, `apply` |
| `it` | 생략할 수 없다. 대신 원하는 이름으로 바꿀 수 있다 | `let`, `also` |

```kotlin
val name = "Kotlin"

name.run { println(length) }               // this.length에서 this를 생략
name.let { println(it.length) }            // it으로 불러야 한다
name.let { text -> println(text.length) }  // it 대신 이름을 붙일 수 있다
```

`this`로 부르는 쪽은 객체의 **멤버를 여러 번 다룰 때** 짧게 쓸 수 있고, `it`으로 부르는 쪽은 객체를 **다른 함수의 인자로 넘길 때** 읽기 좋습니다.

`it`과 `this`가 각각 무엇이고 왜 함수마다 다른지는 [Kotlin의 it과 this: 블록 안에서 객체를 부르는 두 이름](/blog/groups/programming_language/kotlin/kotlin_it_and_this)에서 따로 정리했습니다.

### 2.2 블록이 끝나면 무엇을 돌려주는가

| 반환값 | 뜻 | 해당 함수 |
| --- | --- | --- |
| 람다 결과 | 블록의 **마지막 식**의 값 | `let`, `run`, `with` |
| 객체 자신 | 블록에서 무엇을 하든 **원래 객체** | `apply`, `also` |

```kotlin
val length = "Kotlin".let { it.length }      // 6 — 마지막 식의 값
val same = "Kotlin".also { println(it) }     // "Kotlin" — 객체 자신
```

### 2.3 한눈에 보기

두 기준을 겹치면 다섯 함수의 자리가 정해집니다.

| | 람다 결과를 반환 | 객체 자신을 반환 |
| --- | --- | --- |
| **`this`로 부른다** | `run`, `with` | `apply` |
| **`it`으로 부른다** | `let` | `also` |

`run`과 `with`는 같은 칸에 있습니다. 둘은 하는 일이 같고 **호출하는 모양만** 다릅니다. `run`은 `객체.run { }`처럼 객체 뒤에 붙이고, `with`는 `with(객체) { }`처럼 객체를 인자로 넘깁니다.

## 3. 함수별 사용법

예시에는 아래 두 클래스를 사용합니다.

```kotlin
class Person {
    var name: String = ""
    var age: Int = 0
}

data class User(val name: String, val age: Int)
```

### 3.1 let — null이 아닐 때만 실행하거나, 값을 변환할 때

`it`으로 부르고 **람다 결과**를 반환합니다.

가장 흔한 쓰임은 안전 호출(`?.`)과 함께 쓰는 것입니다. `?.let`은 객체가 `null`이 아닐 때만 블록을 실행하고, 블록 안의 `it`은 `null`이 아닌 타입이 됩니다.

```kotlin
val name: String? = "Kotlin"

val length: Int? = name?.let {
    println("이름: $it")
    it.length               // 마지막 식이 반환값
}
```

`name`이 `null`이면 블록은 실행되지 않고 `length`는 `null`이 됩니다.

객체를 다른 값으로 바꾸는 용도로도 씁니다.

```kotlin
val user = User("Alice", 28)
val greeting = user.let { "안녕하세요, ${it.name}님" }
```

### 3.2 run — 객체의 멤버로 작업한 뒤 결과를 얻을 때

`this`로 부르고 **람다 결과**를 반환합니다. 객체의 멤버를 여러 번 쓰면서 마지막에 결과값이 필요할 때 어울립니다.

```kotlin
val sb = StringBuilder()

val result = sb.run {
    append("Hello, ")
    append("Kotlin!")
    toString()              // 마지막 식이 반환값
}
```

`run`은 `?.`과 함께 쓸 수 있어서, `null`일 수 있는 객체의 멤버를 다룰 때 `with`보다 편합니다.

```kotlin
val user: User? = findUser()
val summary = user?.run { "$name ($age)" }
```

객체 없이 블록만 실행하는 형태도 있습니다. 여러 문장을 묶어서 값 하나를 만들어야 할 때 씁니다.

```kotlin
val port = run {
    val text = System.getenv("PORT")
    text?.toIntOrNull() ?: 8080
}
```

### 3.3 with — 이미 있는 객체로 여러 작업을 할 때

`this`로 부르고 **람다 결과**를 반환합니다. `run`과 같은 일을 하지만, 객체를 괄호 안에 인자로 넘깁니다.

```kotlin
val user = User("Alice", 28)

val summary = with(user) {
    "$name ($age)"
}
```

"이 객체를 가지고(with) 다음 일을 한다"로 읽힙니다. 반환값을 쓰지 않고 객체의 멤버를 연달아 호출하는 용도로도 자주 씁니다.

```kotlin
with(user) {
    println(name)
    println(age)
}
```

`with(객체)` 형태에는 `?.`을 붙일 자리가 없습니다. 그래서 `null`이 아닌 객체에 쓰고, `null`일 수 있으면 `?.run`을 씁니다.

### 3.4 apply — 객체를 만들면서 설정할 때

`this`로 부르고 **객체 자신**을 반환합니다. 블록 안에서 프로퍼티를 설정하고 나면 설정이 끝난 객체가 그대로 나오므로, 객체 생성과 초기화를 한 번에 쓸 수 있습니다.

```kotlin
val person = Person().apply {
    name = "Minji"
    age = 25
}                           // Person 객체가 반환된다
```

블록의 마지막 식이 무엇이든 반환값에는 영향을 주지 않습니다. 이 점이 `run`과 다릅니다.

```kotlin
val a = Person().apply { name = "Minji" }   // Person
val b = Person().run { name = "Minji" }     // Unit — 대입문은 값이 없다
```

### 3.5 also — 객체는 그대로 두고 부가 작업을 끼워 넣을 때

`it`으로 부르고 **객체 자신**을 반환합니다. 로그 출력이나 검증처럼, 객체를 바꾸지 않고 "하는 김에 이것도" 처리할 때 씁니다.

```kotlin
val numbers = mutableListOf(1, 2, 3)
    .also { println("추가 전: $it") }
    .apply { add(4) }
    .also { println("추가 후: $it") }
```

`also`는 객체를 그대로 돌려주므로 호출 흐름 중간에 넣었다가 빼도 결과가 바뀌지 않습니다.

## 4. 무엇을 쓸지 고르는 방법

질문 두 개에 답하면 함수가 정해집니다.

1. 블록이 끝난 뒤 **객체 자신**이 필요한가, **다른 결과값**이 필요한가
2. 블록 안에서 객체의 **멤버를 주로 다루는가**, 객체를 **통째로 넘기는가**

| 하려는 일 | 함수 |
| --- | --- |
| 객체를 만들면서 프로퍼티를 설정한다 | `apply` |
| 객체는 그대로 두고 로그·검증을 끼워 넣는다 | `also` |
| `null`이 아닐 때만 실행한다 | `?.let` |
| 객체를 다른 값으로 변환한다 | `let` |
| 객체의 멤버로 계산해서 결과를 얻는다 | `run` |
| 이미 있는 객체의 멤버를 연달아 호출한다 | `with` |

헷갈리기 쉬운 두 쌍은 이렇게 구분합니다.

| 비교 | 같은 점 | 다른 점 |
| --- | --- | --- |
| `let` vs `run` | 람다 결과를 반환 | `let`은 `it`, `run`은 `this` |
| `apply` vs `also` | 객체 자신을 반환 | `apply`는 `this`, `also`는 `it` |

## 5. 주의할 점

### 5.1 겹쳐 쓰면 this와 it이 누구인지 흐려진다

스코프 함수 안에 스코프 함수를 넣으면 `it`이나 `this`가 어느 객체인지 한눈에 알기 어렵습니다.

```kotlin
user?.let {
    it.address?.let {
        println(it.city)    // 이 it은 address다. 바깥의 user는 가려졌다
    }
}
```

겹쳐야 한다면 `it`에 이름을 붙입니다.

```kotlin
user?.let { user ->
    user.address?.let { address ->
        println("${user.name}: ${address.city}")
    }
}
```

### 5.2 apply 안에서는 같은 이름의 변수가 먼저 선택된다

`this`를 생략하면 바깥의 변수와 객체의 프로퍼티 이름이 같을 때 문제가 됩니다.

```kotlin
fun createPerson(name: String): Person {
    return Person().apply {
        name = name         // ❌ 양쪽 모두 파라미터 name을 가리킨다
    }
}
```

블록 안에서 `name`은 프로퍼티보다 가까이 있는 파라미터를 먼저 가리킵니다. 파라미터에 자기 자신을 대입하는 코드가 되어 컴파일 에러가 납니다. 이럴 때는 `this`를 적습니다.

```kotlin
fun createPerson(name: String): Person {
    return Person().apply {
        this.name = name    // ✅ 왼쪽은 프로퍼티, 오른쪽은 파라미터
    }
}
```

### 5.3 짧아진다고 항상 읽기 좋은 것은 아니다

`null` 검사 하나만 필요한 자리라면 `if`가 더 분명할 때가 많습니다.

```kotlin
name?.let { println(it) }

if (name != null) println(name)
```

스코프 함수는 코드를 줄이는 도구이지 반드시 써야 하는 문법이 아닙니다. 읽는 사람이 `this`와 `it`이 무엇인지 한 번 더 생각해야 한다면 풀어 쓰는 편이 낫습니다.

## 6. 마무리

스코프 함수 다섯 개는 **객체를 무엇이라고 부르는가(`this` / `it`)** 와 **무엇을 돌려주는가(람다 결과 / 객체 자신)** 두 기준으로 구분됩니다.

| 함수 | 객체를 부르는 이름 | 반환값 | 주된 용도 |
| --- | --- | --- | --- |
| `let` | `it` | 람다 결과 | `null`이 아닐 때 실행, 값 변환 |
| `run` | `this` | 람다 결과 | 멤버로 작업하고 결과 계산 |
| `with` | `this` | 람다 결과 | 이미 있는 객체의 멤버를 연달아 사용 |
| `apply` | `this` | 객체 자신 | 객체 생성과 설정 |
| `also` | `it` | 객체 자신 | 로그·검증 같은 부가 작업 |

객체 자신이 계속 필요하면 `apply`나 `also`, 새로운 결과값이 필요하면 `let`, `run`, `with` 중에서 고르면 됩니다.
