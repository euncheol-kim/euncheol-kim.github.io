## 1-3. JSX (Javascript + XML/HTML)
JSX는 자바스크립트의 확장 문법이다. 

### 1-3-1. JSX의 역할
- JSX는 내부적으로 <b>XML/HTML코드를 자바스크립트로 변환하는 과정</b><sup> [부록 3](#e-3) </sup>을 거친다.
- JSX로 코드를 작성해도 트랜스파일러 덕분에 최종적으로는 자바스크립트 코드가 나온다. (React Element)

### 1-3-2. JSX의 장점
- 코드가 간결해진다. 
- 가독성이 향상된다.
- Injection Attack 해킹 방법을 방어하여 보안성이 올라간다.

## 1-4. Element
### 1-4-1. (React) Element의 특징
- Element는 자바스크립트 객체 형태로 존재한다.
- 🔥 Element 객체는 맘대로 변경할 수 없는 <b>불변성</b>을 갖는다. 즉, <u>한 번 생성된 Element는 변하지 않기 때문에 Element 생성 후에는 `children`이나 `attributes`를 바꿀 수 없다.</u>
- 화면에 변경된 Element들을 보여주기 위해서는 기존 Element를 변경하는 것이 아니라, 새로운 Element를 만들고 바꿔주어야 한다. 이유는 <u>React가 상태(State)나 Props의 변경을 감지하고 리렌더링을 결정하는 핵심 기준은 바로 "메모리 주소(참조값)의 변경"이기 때문이다.</u> 여기서 <b>"React가 상태(State)나 Props의 변경을 감지한다."</b> 라는 의미는 <b> "새로운 데이터를 담은 완전히 새로운 객체로 교체 했다."</b>라는 의미다.

### 1-4-4. Element 렌더링 하기
```javascript
<div id="root"></div>
```
위 코드는 단순한 HTML 태그이지만, React에서는 아주 중요한 필수적인 코드이다.
React는 <b>`<div>`태그 안에 리액트 Element들이 렌더링 되고 이것을 <u>Root DOM node</u>라고 부른다.</b>
이 `<div>`태그 안에 있는 모든 것들이 React DOM에 의해서 관리된다.

![](./root-dom-node.png)
오직 React만으로 만들어진 모든 웹사이트들은 단 하나의 <b>Root DOM node</b>를 가지게 된다.
반면에 기존에 있던 웹사이트에 추가적으로 리액트를 연동하게 되면, 여러개의 분리된 수많은 <b>Root DOM node</b>들을 가질 수도 있다.

<br/>

🧑🏻‍💻 [예제 코드] root `<div>`에 React Element를 렌더링하는 코드
```javascript
const element = <h1> 안녕, 리액트!</h1>;
const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(element);
```
위 코드는 `element`를 생성하고, 생성된 `element`를 `root div`에 렌더링 하는 코드이다.
`createRoot()` 함수는 파라메터로 받은 React `element`를 <b>Root DOM node</b>에 렌더링하는 역할을 한다.

⚠️ 하나만 짚고 넘어가고 싶은 것은 React Element와 HTML의 Element는 서로 다른 개념임을 기억한다. <b>React의 Element</b>는 React의 Virtual DOM에 존재하는 것이고, <b>HTML의 Element</b>는 실제 브라우저의 DOM에 존재하는 것이다. <b>React의 Element가 렌더링되는 과정</b>은 <u>Virtual DOM에서 실제 DOM으로 이동하는 과정이라고 설명할 수 있다.</u>

### 1-4-5. 렌더링된 Element 업데이트 하기
렌더링 된 Element를 업데이트 하기 위해서는 다시 생성해야 한다.
- Element는 한 번 생성되면 바꿀 수 없는 <b>불변성의 특징</b>을 가지기 때문에 반드시 다시 생성해야한다.

🧑🏻‍💻 [예제 코드] Element 업데이트 예제 코드
```javascript
function tick() {
    const element = (
        <div>
            <h1> 안녕, 리액트!</h1>
            <h2> 현재 시간: {new Date().toLocaleTimeString()}</h2>
        </div>
    );

    const root = ReactDOM.createRoot(document.getElementById('root'));
    root.render(element);
}

setInterval(tick, 1000);
```
<b>tick()함수는 현재 시간을 포함하고 있는 Element를 생성하여 root div에 렌더링 하는 역할을 한다. 그리고 자바스크립트의 setInterval=()함수를 사용해서 Ticket=()함수를 매초마다 호출하고 있다.</b>

이 코드는 매초마다 화면에 새로운 시간이 나오게 될 것이다. 🔥 내부적으로는 tick()함수가 호출될 때마다 기존 Element를 변경하는 것이 아니라 <b><u>새로운 Element를 생성</u></b>해서 바꿔치기 한다.

### 🌱 부록
### <span id="e-1">[1] Virtual DOM</span>
브라우저는 <b>Real DOM</b> 이라는 객체 모델을 사용한다.
브라우저에서 <u>요소(UI)가 변경되면</u> <b>Real DOM을 통해 레이아웃을 계산하고 다시 그리는 작업을 진행한다.</b>
이를 <b>렌더링</b>이라고 하는데 <b><u>Real DOM을</u> 통해 렌더링 작업을 진행하는 것은 매우 비용이 많이 드는 작업</b>이다.


`Virtual DOM`은 Real DOM의 가벼운 자바스크립트의 객체 복사본이며, 렌더링 비용 문제를 해결한다.
Virtual DOM은 Real DOM에 반영되기 전에 미리 수정해보는 설계도나 초안으로 비유할 수 있다.
Virtual DOM은 실제 화면에 렌더링되지 않고 메모리상에만 존재하기 때문에, 생성하고 조작하는 속도가 Real DOM과 비교할 수 없을 정도로 매우 빠르다.

<b> 화면 업데이트 과정 </b>
1. 상태 업데이트 (State Change) 
: 데이터가 변경되면, UI에 새로운 상태를 반영한 새로운 Virtual DOM 트리를 메모리에 그린다.
2. 비교 (Diffing)
: 방금 만든 <b>새로운 Virtual DOM</b>과 변경 전의 <b>이전 Virtual DOM을 비교</b>한다. 
내부적으로 트리를 순회하면서 정확히 어느 노드(요소)가 추가, 삭제, 또는 수정되었는지 찾아낸다.
3. 적용 (Patching/Reconciliation)
: 차이점을 모두 파악했다면, 변경된 부분들만 모아서 Real DOM에 단 한 번만 적용(Patch)한다.

이 과정은 매우 유의미하다. 만약 Real DOM만 사용했다면 <b>Reflow & Repain</b> 작업이 발생하게 된다.
만약 버튼 요소의 크기나 텍스트가 계속적으로 변경된다면, 매번 화면 전체의 레이아웃을 재계산(Reflow)하고 결과 변경에 따라 다시 그려야한다(Repain). <b>Virtual DOM</b>의 객체는 <u>변경된 요소만 타겟팅하여 변경된 값을 적용한다. 여러번의 비교는 이루어질 수 있지만, 단 한 번의 적용을 통해 화면 렌더링 비용을 극단적으로 줄일 수 있다.</u>

### <span id="e-2">[2] 컴포넌트 기반의 구조</span>
```javascript
<MyComponent>
  <div id="box">
    <span className="inner-item">Hello</span>
  </div>
</MyComponent>
```

```javascript
{
  type: MyComponent, 
  props: {
    children: {
      type: 'div', 
      props: {
        id: 'box',
        children: {
          type: 'span',
          props: {
            className: 'inner-item',
            children: 'Hello'
          }
        }
      }
    }
  }
}
```
#### 컴포넌트의 특징
- 하나의 컴포넌트는 여러개의 자식 컴포넌트들을 포함할 수 있고, 
자식 컴포넌트들을 모두 쭉 분해해보면 결국 HTML 태그가 나온다.
- <b>props</b>: 요소에 부여된 속성(Attributes)들이 고스란히 담기는 곳이다.
- <b>children</b>: 태그 안의 자식 내용이나 하위 컴포넌트들은 따로 분리되어 존재하는 것이 아니라, 모두 이 `props`객체 안의 `children`이라는 이름으로 통합되어 관리된다.

React는 컴포넌트들이 모여 하나의 페이지를 만든다. <b>컴포넌트</b>는 레고 블록으로 비유할 수 있다.
컴포넌트를 정의하는 단위는 매우 다양할 수 있다. 가장 작은 단위의 컴포넌트로 나누거나 기능이라는 의미 단위의 <b>컴포넌트를 잘 나누어 개발을 진행한다면 컴포넌트의 재사용성이 매우 높아질 것</b>이며 이는 <b>개발 단축</b>과 <b>유지보수</b>에 큰 영향을 주게된다. 이뿐만이 아니다. 소프트웨어 공학에서는 <b>높은 응집도와 낮은 결합도를 유지 시키는 것이 매우 중요하다고 이야기하는데 이 또한 지켜지게 된다.</b>

<Callout type="info"> 
<span id="ocp-principle">재사용성과 재활용</span>
- 재사용: 이미 만들어진 것을 다시 사용이 가능한 성질
- 재활용: 다시 활용이 가능한 자원을 가공하여 새로운 제품을 만드는 것 
</Callout>

### <span id="e-3">[3] JSX는 XML/HTML코드를 자바스크립트로 변환하는 과정을 거친다.</span>
브라우저는 HTML/CSS/JavaScript 이 세가지만 이해를 할 수 있다.
JSX는 자바스크립트 코드 안에 HTML 마크업을 섞어 쓴 매우 독특한 확장 문법이다.
따라서 브라우저가 JSX문법을 그대로 읽게 되면 문법(Syntax Error)를 일으켜 렌더링을 멈춘다.
그래서 개발자가 작성한 JSX코드를 브라우저가 온전히 읽고 실행할 수 있도록 자바스크립트 코드로 번역한다.
이 번역의 과정은 <b> 트랜스파일러 </b> 도구가 담당하여 처리된다. (종류: Babel 등)

<br/>

```javascript
const element = <h1 id="box">Hello, World!</h1>;
```
예를 들어, `<h1 id="box">Hello, World!</h>` 형태로 작성된 코드는 내부적으로 
`React.createElement('h1', { id: "box" }, 'Hello, World')`로 변환된다.
- 첫 번째 인자 <b>type</b> ( h1 ): 생성할 HTML의 태그 이름 또는 React Component.
- 두 번째 인자 <b>props</b> ( \{id: "box"} ): 태그에 부여된 속성 만약 속성이 없었다면 null 할당
- 세 번째 인자 <b>children</b> ( 'Hello, World!' ): 태그 안에 들어갈 자식의 내용

🔥 `React.createElement('h1', { id: "box" }, 'Hello, World')`를 통해 객체가 만들어지는데 이 객체를 React 생태계 안에서 <b> <span id="react-element">React Element</span> </b>라고 부른다. 이 함수를 통해 만들어진 <b> React Element는 </b> <b><u>화면을 효율적으로 관리하기 위해 사용하는 자바스크립트의 객체 Virtual DOM의 구성요소</u></b>가 만들어지는 것이다.

내부적으로 처리되어진 위의 `React.createElement`는 아래와 같은 비슷한 객체가 나오게 된다.
비슷한 이라고 표현한 이유는 몇 개의 프로퍼티 키가 더 있는 것으로 확인이 되어지는데 지금 다루지 않으려고 한다.
```javascript
const element = {
    type: 'h1'
    props: {
        id: 'box',
        children: 'Hello, World'
    },
}
``` 
type은 명확하게 태그 이름이 들어가는 것을 알 수 있다. <b>props</b>는 <b>태그의 속성과 자식 요소를 담는다.</b>  
🔥 <u>여기서 중요한 포인트는 `children`도 `props`의 일부라는 것이다.</u>
중요한 설명을 조금 더 붙이면 <u>`props`는 부모 컴포넌트가 자식 컴포넌트에게 전달하는 데이터나 설정값(속성)이고</u>, <u>`children`은 컴포넌트의 여는 태그와 닫는 태그 사이에 들어가는 모든 내용이다.</u>

<b>🔥 결과적으로 이 `React.createElement` 함수가 수십, 수백 번 실행되며 만들어진 React Element들이 트리 구조로 쭉 연결된 것이 Virtual DOM이다. </b> Virtual DOM의 실행순서와 관련해서는 [1-1:1. Virtual DOM](#e-1)을 참고하자.

### 🔥 [4] React 19 이전의 비효율적인 재실행과 개선된 현재
React19 이전에는 데이터(상태)가 하나라도 바뀌면, 화면을 최신 상태로 유지하기 위해 해당 <b>컴포넌트(함수)를 처음부터 끝까지 다시 실행했다.</b> 이때 심각한 문제가 발생하는데, 함수가 다시 실행되면서, 그 안에 있던 변수나 함수들도 <b>'완전히 새로운 메모리 주소'를 배정받아 매번 새로 만들어지게 된다.</b> 값이 똑같아도 말이다. 이러한 이유로 <u>React는 값의 변경이 없는 자식 컴포넌트들에 대해서도 메모리 주소가 변경되었기 때문에 불필요한 화면을 다시 그리는 성능 저하 문제를 야기시켰다. </u>

React19 이전에는 이러한 성능 저하 문제를 막기 위해 React에게 "이 데이터(또는 함수)는 바뀐 게 없으므로 새로 만들지 말고 예전 걸 사용하라"라고 일일이 지시를 내렸는데 이때 사용한 도구가 `useMemo`와 `useCallback`이다.

🧑🏻‍💻 [예시 코드] React19 이전에 개발자들이 성능 저하를 막기 위해 사용한 코드 예시
```javascript
import { useCallback, useMemo } from 'react';

interface Props {
  userId: string;
}

export const UserProfile = ({ userId }: Props) => {
  // 1. useCallback: 함수가 매번 새로 생성되는 것을 수동으로 막음
  const handleSave = useCallback(() => {
    console.log(`${userId} 저장 완료`);
  }, [userId]); // userId가 바뀔 때만 새로 만들어라!

  // 2. useMemo: 객체가 매번 새로 생성되는 것을 수동으로 막음
  const profileStyle = useMemo(() => ({
    backgroundColor: 'white',
    padding: '20px'
  }), []); // 빈 배열: 처음 한 번만 만들고 평생 재사용해라!

  return (
    <ChildComponent onSave={handleSave} style={profileStyle} />
  );
};
```
이러한 방식의 단점은 개발자가 "안제, 어떤 데이터를 어떤 조건에서 재사용할지" 고민하게 만들었다.
또한 코드가 매우 지저분해지고, 실수로 하나라도 빼먹을 경우 성능 버그가 발생했다.

React19로 넘어와서는 React Compiler가 도입되어 `useMemo`나 `useCallback`을 모두 지우고 아주 자연스럽고 원초적인 자바스크립트 코만만 작성하면 된다. <u>코드를 빌드(변환)하는 과정에서 React Compiler가 코드를 싹 훑어보고, 필요한 최적화 코드를 자동으로 끼워 넣어준다.</u>

🧑🏻‍💻[예시 코드] React Compiler로 개선된 코드
```javascript
interface Props {
  userId: string;
}

export const UserProfile = ({ userId }: Props) => {
  // 💡 수동 캐싱 코드가 전부 사라졌습니다!
  // React Compiler가 알아서 함수와 객체의 변경 여부를 추적하고 재사용합니다.
  
  const handleSave = () => {
    console.log(`${userId} 저장 완료`);
  };

  const profileStyle = {
    backgroundColor: 'white',
    padding: '20px'
  };

  return (
    <ChildComponent onSave={handleSave} style={profileStyle} />
  );
};
```
이러한 변화 덕분에 성능을 위해 감싸주었던 `useMemo`와 `useCallback`을 탈피하여 깔끔한 코드를 작성할 수 있게 되었다.
