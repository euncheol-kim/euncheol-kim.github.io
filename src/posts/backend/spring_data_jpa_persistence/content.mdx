## 1. 영속성 컨텍스트 (Persistence Context)
영속성 컨텍스트는 JPA가 DB와 직접 연결하지 않고 엔티티를 관리하는 메모리 공간입니다.
JPA를 통해 엔티티를 저장하거나 조회하면, 이 객체는 "영속성 컨텍스트"에 보관됩니다.

### 1-1. 필요성
#### [1] 📍패러다임의 불일치
| 패러다임 | 설명 |
|---|---|
| 객체지향 애플리케이션 | 데이터와 행위를 캡슐화하며, 객체 간의 참조를 통해 탐색한다. |
| 관계형 데이터베이스 | 데이터를 테이블 형식으로 정규화하여 저장하고, PK와 FK를 통해 테이블 간의 관계를 맺는다. |

#### [2] 📍버퍼와 캐시의 역할
애플리케이션(메모리)과 DB(디스크)사이에서 버퍼와 캐시의 역할을 수행합니다. 
이를 통해 객체의 상태를 안전하고 효율적으로 동기화합니다. 

📍영속성 컨텍스트는 아래와 같은 4가지 핵심 메커니즘을 제공하기 위해 존재합니다.
| 메커니즘 | 설명 |
|---|---|
| <span id="identity-guarantee"> **동일성(Identity) 보장** </span> | 동일한 트랜잭션 내에서 같은 식별자(ID)를 가진 엔티티를 조회할 때, 항상 메모리 주소가 같은 동일한 객체 인스턴스를 반환합니다. 이는 1차 캐시 덕분이며, 데이터베이스 로우(Row)를 객체지향적인 관점에서의 '객체'로 온전히 취급할 수 있게 해줍니다. (entityA == entityB가 참이 됨) |
| <span id="dirty-checking">**변경 감지(Dirty Checking)**</span> | 객체의 상태가 변경되었을 때, 개발자가 명시적으로 UPDATE 쿼리를 실행하지 않아도 영속성 컨텍스트가 엔티티의 초기 상태(스냅샷)와 현재 상태를 비교하여 트랜잭션 커밋 시점에 자동으로 UPDATE 쿼리를 생성하여 DB에 반영합니다. 이는 순수한 비즈니스 로직(Domain 로직) 작성에만 집중할 수 있도록 해주는 가장 강력한 이유입니다. |
| <span id="transactional-write-behind">**트랜잭션을 지원하는 쓰기 지연 (Transactional Write-Behind)**</span> | 엔티티를 저장하거나 수정할 때마다 즉시 DB에 쿼리를 보내지 않고, 영속성 컨텍스트 내의 '쓰기 지연 SQL 저장소'에 쿼리를 차곡차곡 모아둡니다. 트랜잭션이 커밋되는 순간(Flush) 모아둔 쿼리를 한 번에 DB로 전송하여 네트워크 통신 비용을 최소화하고 성능을 최적화합니다. |
| <span id="lazy-loading">**지연 로딩 (Lazy Loading)**</span> | 연관된 엔티티(예: 외래 키로 묶인 데이터)를 실제로 사용할 때까지 DB 조회를 지연시키는 기능입니다. 영속성 컨텍스트가 프록시(Proxy) 객체를 제공함으로써, 불필요한 데이터베이스 접근을 막아줍니다. |

### 1-2. 영속성 상태의 종류
| 영속성 상태 | 설명 |
|---|---|
| 비영속(Transient) | 막 객체가 생성되어 DB와 아무 관련이 없는 상태 (new Obejct) |
| 영속 (Managed) | 영속성 컨텍스트(EntityManager)가 관리하는 상태(em.persiste()) |
| 준영속 (Detached) | 관리되다가 분리된 상태 |
| 삭제 (Removed) | 삭제하기로 표시된 상태 (em.remove) |

기본적으로 JPA는 엔티팉의 상태 변화를 연관된 다른 엔티티로 전파하지 않습니다.
예를 들어, 부모 객체를 persist()(저장) 한다고 해서 자식 객체까지 자동으로 저장되지 않습니다.
자식도 개별적으로 persist()를 해줘야합니다. 이러한 번거로움을 해결하기 위해 JPA는 CascadeType옵션을 제공합니다.
