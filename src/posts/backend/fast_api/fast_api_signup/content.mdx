## [1-2] User모델의 생성과 연관관계 지정
<u>요구사항에서는 User와 Todo의 관계가 1:N이다.</u> 이를 반영하기 위해 Todo를 아래처럼 작성한다.

🧑🏻‍💻<b>[예제 코드]: User와 Todo의 관계를 1:N로 반영하기 위한 <u>Todo 모델 생성</u></b>
```python {25, 29}
from datetime import datetime

from sqlalchemy import Integer, String, Boolean, DateTime, ForeignKey, func
from sqlalchemy.orm import Mapped, mapped_column, relationship

from database.orm import Base

class Todo(Base):
    __tablename__="todo"

    id: Mapped[int] = mapped_column(
        Integer,
        primary_key=True,
        autoincrement=True,
    )
    title: Mapped[str] = mapped_column(
        String(255),
        nullable=False,
    )
    is_done: Mapped[bool] = mapped_column(
        Boolean,
        nullable=False,
        default=False,
    )
    user_id: Mapped[int] = mapped_column(   # DB 테이블에 생성되는 외래키 컬럼 => JPA의 @JoinColumn(name="user_id")와 같다.
        ForeignKey("user.id"),
        nullable=True
    )
    user: Mapped["User"] = relationship(      # DB에는 존재하지 않지만 연관된 객체를 바로 탐색(객체 그래프 탐색)할 수 있게 해주는 가상 속성
        back_populates="todos"
    )

    def __repr__(self) -> str:
        return f"<Todo(id={self.id}, title='{self.title}', is_done={self.is_done})>"
```
수정을 한 Todo는 user_id와 user 속성값이 추가되었다.

1. user_id
    
    -   
        **user_id: Mapped[int] (물리적 컬럼 생성)**
        : 실제 DB의 todo 테이블에 user_id라는 정수형 커럼을 만든다.
    -   
        **ForeginKey("user.id") (DB제약조건 강제)**
        : DB엔진에게 "이 컬럼은 반드시 user 테이블의 id 컬럼에 존재하는 값만 가져야 한다"는 외래키 참조 무결성을 강제한다. 중요한 핵심은 user.id가 파이썬 클래스가 아닌 **실제 DB테이블의 이름과 컬럼**을 가리킨다는 것이다.
    -
        **nullable=True (관계의 선택성)**
        : 특정 사용자에 소속되지 않은(주인이 없는) Todo 데이터도 DB에 저장할 수 있도록 허용한다.
2. user

    -
        **user: Mapped["User"] (객체 그래프 탐색)**
        : DB에서 todo 데이터를 가져왔을 때, todo.user_id 처럼 숫자 값만 보는것이 아니라 todo.user.username처럼 연관된 User 객체의 속성에 마침표를 찍어 바로 접근 할 수 있도록 한다.

    - 
        **relationship(...) (가상 속성 선언)**
        : 이 속성은 실제 DB 테이블의 컬럼으로 만들어지지 않는다. SQLAlchemy가 런타임에 두 테이블을 조언(Join)하여 파이썬 객체로 조립해 주기 위해 사용하는 ORM 전용 설정이다.

    -
        **back_populates="todos" (양방향 메모리 동기화)**
        : 반대편 User 클래스에 정의될 todos 속성과 연결고리를 만든다. 파이썬 코드 상에서 todo.user = some_user 라고 할당 되면, 즉시 some_user.todos 리스트에도 이 todo 객체가 자동으로 추가되도록 메모리 상태를 동기화해준다.
    
<br/>
🧑🏻‍💻<b>[예제 코드]: User와 Todo의 관계를 1:N로 반영하기 위한 <u>User 모델 생성</u></b>
```python { 13, 23, 28 }
# models.py
from datetime import datetime

from sqlalchemy import Integer, String, Boolean, DateTime, ForeignKey, func
from sqlalchemy.orm import Mapped, mapped_column, relationship

from database.orm import Base

# ... 
# ...
class User(Base):
    id: Mapped[int] = mapped_column(primary_key= True)
    email: Mapped[str] = mapped_column(
        String(255),
        unique=True,
        index=True,
        nullable=False,
    )
    hashed_password: Mapped[str] = mapped_column(
        String(255),
        nullable=False,
    )
    created_at: Mapped[datetime] = mapped_column(
        DateTime,
        server_default=func.now(),
        nullable=False,
    )
    todos: Mapped[list["Todo"]] = relationship(
        back_populates="user",
        cascade="all, delete-orphan",
    )
```

1.  todos

    -
        list["Todo"]
        : 한 명의 유저가 여러 개의 할 일을 가질 수 있도록 list 타입으로 묶고, 대상 모델을 Todo처럼 문자열로 적어준 것은 순환 참조 에러를 방지하기 위한 파이썬 백엔드의 표준 관례이다.
    -   
        back_populates="user"
        : <b>Todo 클래스에 있는 user 속성과 연결하여 양방향으로 연결한다는 의미</b>다.

    -   
        casecade="all, delete-orphan"
        : 영속성 전이를 설정한다. all은 부모가 저장되거나 삭제될 때, 자식들도 똑같이 그 상태를 따라간다는 것이고 delete-orphan은 부모의 todos 리스트에서 특정 Todo 객체를 제거하면(연결을 끊으면) DB 테이블에서도 해당 Todo 데이터를 완전히 DELETE 해버린다. **주의해야할 점은**, 처음부터 user_id가 NULL인 할 일은 특정 사용자와 관계를 가진적이 없기 때문에 ORM은 이를 고아객체로 판단하지 않아 delete-orphan의 대상이 되지 않는다. 이는 요구되어지는 비즈니스에 따라 다르겠지만 익명 사용자의 할 일은 유지하고, 특정 사용자에게만 속했던 할 일만을 사용자를 삭제할 때 정리하려는 요구사항으로 해석될 수 있다.

2.  created_at

    -
        DateTime
        : SQLAlchemy에서 제공하는 데이터 타입 클래스로, 데이터베이스에 저장될 때, 자동으로 현재 시간을 저장한다.
    -
        server_default=func.now()
        : server_default는 컬럼 값을 애플리케이션이 아니라 데이터베이스에서 직접 생성하도록 지시하는 옵션이다.
        func.now()는 SQLAlchemy의 내장 함수 모듈로, 사용하면 MySQL 내부의 NOW() 함수가 실행되어 현재 시간이 저장된다.

    -
        nullable=False
        : 데이터베이스에 저장될 때, 자동으로 현재 시간을 저장한다.

3. email

    -
        unique=True
        : 해당 컬럼에 중복된 값이 저장되지 않도록 한다.
    -
        index=True
        : 해당 컬럼을 인덱스로 설정하여, 이메일 기준으로 데이터를 조회할 때 DB가 전체 데이터를 순차적으로 탐색하지 않고 인덱스를 활용해 값을 더 빠르게 검색할 수 있도록 한다.

### [1-2-1] 이미 FastAPI 프로젝트가 빌드되어 테이블이 생성된 상황을 가정한다.
위의 코드를 작성하기 전에, User와 Todo 모델이 이미 빌드되어 테이블이 생성된 상황을 가정한다.
코드를 수정한 이후 DB관점에서는 Todo 테이블에 user_id 컬럼이 추가된 상태이다.

#### (1) db_conection.py
```python
# db_conection.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

# DB 연결 정보 설정
DATABASE_URL = "mysql+pymysql://root:password@localhost:3306/fastapi_db"

# 엔진 설정
engine = create_engine(DATABASE_URL, echo=True)

SessionFactory = sessionmaker(
    autocommit=False,
    autoflush=False,
    expire_on_commit=False,
    bind=engine
)
```

from sqlalchemy.orm import DeclarativeBase

현재 코드가 위와 같을 때, 중요한 포인트는 `Base.metadata.create_all(engine)` 코드 부분인데,
`create_all()`은 <u> 존재하지 않는 테이블에 대해서 생성만 하고, 테이블 구조는 변경하지 않는다.</u>

<br/>

```text
sqlalchemy.exc.OperationalError: (pymysql.err.OperationalError) (1054, "Unknown column 'todo.user_id' in 'field list'")
```
이 상태로 빌드하면 정상적으로 구동되는듯 하지만, todo와 관련된 데이터 리소스를 요청하게 되면 위와 같은 오류가 발생할 수 있다. <u>이는 SQLAlchemy ORM은 파이썬 코드의 쿼리를 SQL로 변환하여 실행하는데, 모델 코드나 쿼리문에는 user_id를 참조하고 있지만 실제 DB 스키마에는 해당 컬럼이 없어 DB 엔진(MySQL)이 1054 에러를 반환한 것이다.</u>

<br/>

```sql
ALTER TABLE todo 
ADD COLUMN user_id INT,
ADD CONSTRAINT fk_todo_user FOREIGN KEY (user_id) REFERENCES user(id);
```
따라서, MySQL에 직접 접근하여 컬럼을 추가하는 작업을 진행해주어야 한다. 위의 코드를 작성해주자. <u>`ADD CONSTRAINT fk_todo_user FOREIGN KEY (user_id) REFERENCES user(id);` 문법은 비즈니스 규칙을 데이터베이스 시스템에 의도적이고 물리적으로 선언(Declaration)하여 단단히 묶어두는 목적이라고 볼 수 있다.</u> 상황에 따라서는 물리적으로 묶을 수도 있지만, 느슨하게 논리적으로 묶어 처리할 수 있음을 기억한다.
최근 개발 패턴에 따르면, DB레벨에서 "물리적으로 묶는 행위"는 안티 패턴으로 간주하는 경우가 많다.
