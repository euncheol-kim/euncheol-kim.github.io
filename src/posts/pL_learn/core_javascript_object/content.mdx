## 1. 객체
객체는 다양한 데이터를 담을 수 있다. 객체는 중괄호`{...}`를 통해서 생성이 가능하다.
중괄호 안에는 <b><u>키(`key`)와 값(`value`)  쌍으로 구성된 프로퍼티(`property`)를 여러 개 넣을 수 있다.</u></b>
<b><u>키에는 문자형 그리고 값엔 모든 자료형이 허용된다.</u></b> 마지막으로 프로퍼티 키는 '이름', '식별자'라고도 불린다.

### 1-1. 객체의 생성
```javascript
let user = new Object(); // '객체 생성자' 문법
let user = {}; // '객체 리터럴' 문법 (🔥주로 사용하는 방식)
```

<br/>

[예제 코드] 객체 생성/추가/삭제, 프로퍼티 값 읽기:
```javascript
// 객체 리터럴로 객체 생성
let user = {
  name: "John",
  age: 30,
  "likes birds": true // 두 단어 이상의 조합에서는 쌍 따옴표로 묶는다.
};

alert(user.name); // John
alert(user["name"]); // John
alert(user.age); // 30
alert(user["age"]) // 30

user.isAdmin = true // 프로퍼티 추가, user = {name: "John", age: 30, likes birds: true, isAdmin: true}
delete user.age; // 프로퍼티 삭제, user = {name: "John", likes birds: true, isAdmin: true}

user["age"] = 30; // 프로퍼티 추가, user = {name: "John", likes birds: true, isAdmin: true, age: 30}
delete user["isAdmin"]; // 프로퍼티 삭제, user = {name: "John", likes birds: true, age: 30}
```

### 1-2. 상수 객체
```javascript
const user = {
  name: "John"
};

user.name = "Pete"; // (*)

alert(user.name); // Pete
```
상수 객체는 `const`로 만들어진 객체를 말한다. 객체가 상수로 만들어진다면 값의 수정이 되지 않을 것 같지만, 수정할 수 있다. <b><u>`const`는 user의 값을 고정하지만, 그 내용은 고정하지 않는다.</u></b>

<br/>

```text
[ const 변수 ]  ---->  [ 객체의 메모리 주소 ]
                             |
                             +--> 프로퍼티1 (name): "Kim" (원시 값 직접 저장)
                             +--> 프로퍼티2 (age) : 30    (원시 값 직접 저장)
                             +--> 프로퍼티3 (bestFriend): [주소 B] ----> 또 다른 객체

```
정확히 설명하자면 <b><u>`const`가 값 자체가 아니라 <font color="steelblue">메모리 주소(참조)</font>를 고정하기 때문이다. 즉, <font color="steelblue">재할당은 금지하지만 내부 데이터 수정은 허용되어진다.</font></u></b> 재할당 금지라는 것은 변수가 가리키는 메모리 주소를 다른 곳으로 바꾸는 것을 말한다. 만약 객체 내부의 값까지 고정시키길 원한다면 <b>Object.freeze()</b> 사용법이나 <b>불변성 관리 방법</b>을 사용해야한다.

## 2. 계산된 프로퍼티
```javascript
-----------------------------------------------------------------------
let fruit = prompt("어떤 과일을 구매하시겠습니까?", "apple");

let bag = {
  [fruit]: 5, // 변수 fruit에서 프로퍼티 이름을 동적으로 받아 온다.
};

alert( bag.apple ); // fruit에 "apple"이 할당되었다면, 5가 출력된다.
-----------------------------------------------------------------------
let fruit = 'apple';
let bag = {
  [fruit + 'Computers']: 5 // bag.appleComputers = 5
};
-----------------------------------------------------------------------
```
객체를 만들 때, 객체 리터럴 안의 프로퍼티 키가 대괄호로 둘러싸여 있다면
이를 계산된 프로퍼티(computed property)라고 부른다.

## 3. 단축된 프로퍼티
[예시 코드 코드] 단축되지 않은 객체의 내부 프로퍼티:
```javascript
function makeUser(name, age) {
  return {
    name: name,
    age: age,
  };
}

let user = makeUser("John", 30);
alert(user.name); // John
```
위의 코드를 보면, 프로퍼티의 키와 값의 이름이 동일함을 알 수 있다.
단축된 프로퍼티는 키와 값의 이름이 동일할 경우, 짧게 작성할 수 있는 문법을 제공한다.
이는 프로퍼티 값 단축 구문(property value shorthand)이라고 한다.

[예시 코드] 프로퍼티 값 단축 구문:
```javascript
function makeUser(name, age) {
  return {
    name, // name: name 과 같음
    age,  // age: age 와 같음
    country: "Republic of Korea"
  };
}
```

## ⭐️ 4. `in` 연산자로 프로퍼티 존재 여부 확인하기
[예시 코드] 존재하지 않는 프로퍼티의 호출:
```javascript
let user = {};
alert( user.noSuchProperty === undefined ); // true는 '프로퍼티가 존재하지 않음'을 의미합니다.
```
Javascript 객체의 중요한 특징중 하나는 다른 언어와는 달리, <b><u>존재하지 않는 프로퍼티에 접근하려 해도 에러가 발생하지 않고 `undeinfed`를 반환한다는 것이다.</u></b>

위처럼 `undefined`와 비교하는 것 이외에도,
`in`연산자는 프로퍼티 존재 여부를 확인할 수 있게 한다.

[문법] in 연산자:
```javascript
"key" in object
```
<br/>
[예시 코드] in 연산자의 사용:
```javascript
let user = { name: "John", age: 30 };

alert( "age" in user ); // user.age가 존재하므로 true가 출력됩니다.
alert( "blabla" in user ); // user.blabla는 존재하지 않기 때문에 false가 출력됩니다.
```

## ⭐️ 5. `for...in`반복문
[문법] for..in 반복문:
```javascript
for (key in object) {
  // 각 프로퍼티 키(key)를 이용하여 본문(body)을 실행한다.
}
```

[예시 코드] for..in을 사용한 코드:
```javascript
let user = {
  name: "John",
  age: 30,
  isAdmin: true
};

for (let key in user) {
  // 키
  alert( key );  // name, age, isAdmin
  // 키에 해당하는 값
  alert( user[key] ); // John, 30, true
}
```

## 6. 객체의 정렬과 관련하여
[예시 코드] 객체 프로퍼티 키를 숫자값으로 지정:
```javascript
const user = {
  0: "Euncheol",
  1: "Republic of Korea",
  2: "Developer"
};

alert( user["0"] ); // Euncheol
alert( user[0] ); // Euncheol
```
객체 프로퍼티의 키는 단순 문자열 뿐만 아니라 숫자형, 심볼형으로도 작성이 가능하며,
문자형이나 심볼형에 속하지 않는 값은 문자열로 자동 형 변환 된다는 것을 기억한다.
위의 코드는 키에 숫자를 넣고 자동 형 변환이 된다는 것을 보여주기 위한 코드이다.

이제 객체 정렬 방식과 관련해서 설명해보고자 한다. 객체와 객체 프로퍼티를 다루다 보면 "프로퍼티엔 순서가 있을까?"라는 의문이 생기게 된다. 반복문은 프로퍼티를 추가한 순서대로 실행될지, 그리고 이 순서는 항상 동일할지에 대한 궁금증이다.

결과적으로, Javascript는 객체를 특별한 방식으로 정렬 시킨다. <font color="steelblue"><b>정수 프로퍼티(integer property)</b></font>는 <b><u>자동으로 정렬</u></b>되고, <font color="steelblue"><b>그 외의 프로퍼티</b></font>는 <b><u>객체에 추가한 순서 그대로 정렬되어진다.</u></b>


[예시 코드] 객체 프로퍼티 키를 정수 프로퍼티로 지정하고, for..in문으로 출력:
```javascript
let codes = {
  "49": "독일",
  "41": "스위스",
  "44": "영국",
  // ..,
  "1": "미국"
};

for (let code in codes) {
  alert(code); // 1, 41, 44, 49
}
```
키가 문자열이 맞긴하나, 코드에 작성하신 "49", "41", "1"과 같이 '정수로 변환할 수 있는 문자열'을 키로 사용할 때는 Javascript 엔진의 특별한 규칙이 적용된다. Javascript는 이런 형태의 키를 `'정수형 프로퍼티(Integer property)'`라고 부르며, <b><u>객체를 순회하거나 키를 뽑아낼 때 작성한 순서(삽입 순서)를 무시하고 자동으로 숫자 오름차순으로 정렬한다.</u></b>

<b><u>작성한 코드처럼 노출해야하는 경우라면, 이러한 내부적 동작 때문에 예상치 못한 버그가 발생할 수 있다.</u></b>
위의 문제를 해결하기 위해서는 프로퍼티 키에 `+`를 붙여주고, 출력시에 또 `+`를 붙여주어 숫자형으로 강제 형 변환하면 된다.

[예시 코드] 객체 프로퍼티 키를 문자열로 지정하고, for..in문으로 출력:
```javascript
----------------------------------------------
let user = {
  name: "John",
  surname: "Smith"
};
user.age = 25; // 프로퍼티를 하나 추가

// 정수 프로퍼티가 아닌 프로퍼티는 추가된 순서대로 나열
for (let prop in user) {
  alert( prop ); // name, surname, age
}
----------------------------------------------
let codes = {
  "+49": "독일",
  "+41": "스위스",
  "+44": "영국",
  // ..,
  "+1": "미국"
};

for (let code in codes) {
  alert( +code ); // 49, 41, 44, 1
}
----------------------------------------------
```

## ⭐️ 7. 참조에 의한 객체 복사
| 구분 | 저장되는 방식 |
|---|---|
| 객체 | 참조에 의해(by reference) 저장되고 복사된다. |
| 원시값(문자열, 숫자, 불린값) | 값 그대로 저장/할당되고 복사된다. |

객체와 원시 타입의 근본적인 차이 중 하나는 객체는 ‘참조에 의해(by reference)’ 저장되고 복사된다는 것이다.
원시값(문자열, 숫자, 불린 값)은 ‘값 그대로’ 저장·할당되고 복사된다.

<br/>

```javascript
let user = {
  name: "John"
};
```
객체는 메모리 어딘가에 저장되고, 변수 user엔 객체를 "참조"할 수 있는 값이 저장된다. (주소값)
따라서, 객체가 할당된 변수를 복사할 땐 객체의 참조 값이 복사되고 객체는 복사되지 않는다.

<br/>

```javascript
let user = { name: "John" };
let admin = user; // 참조값(주소값)을 복사함

admin.name = 'Pete'; // 'admin' 참조 값(주소값)에 의해 변경됨
alert(user.name); // Pete
```
변수는 두 개이지만, 변수엔 동일 객체에 대한 참조 값이 저장된다.
따라서 객체를 복사 받은 admin이 프로퍼티 name을 수정하면 그 수정 사항은 user에도 영향을 미친다.

## ⭐️ 8. 참조에 의한 비교
[예시 코드] 동등 연산자 및 일치 연산자를 통한 객체 비교:
```javascript
let a = {};
let b = a; // 참조에 의한 복사

alert( a == b ); // true
alert( a === b ); // true
```
객체 비교 시 동등 연산자 `==`와 일치 연산자 `===`는 동일하게 동작한다.
비교 시, 피연산자인 두 객체가 동일한 객체인 경우에 참을 반환한다.

## 8. 객체 복사, 병합과 Object.assign
객체가 할당된 변수를 복사하면 동일한 객체에 대한 참조 값이 하나 더 만들어지는 것을 위에서 이해했다.
그런데, 객체를 복제하고 싶다면 어떻게 해야할까? 여기서의 복제란, <b><u>기존에 있던 객체와 똑같으면서도 독립적인 객체를 말한다.</u></b>

우선 Javascript는 객체 복제 내장 메소드를 지원하지 않는다라는 것을 알아두자.
사실 객체를 복제해야 할 일은 거의 없고, 참조에 의한 복사로 해결 가능한 일이 대다수이다.
정말 복제가 필요한 상황이라면 아래와 같은 방법들을 사용하면 된다.

[첫 번째 방법] 순회처리:
```javascript
let user = {
  name: "John",
  age: 30
};

let clone = {};

for (let key in user) {
  clone[key] = user[key];
}

clone.name = "Pete"; // clone의 데이터를 변경한다.

alert( user.name ); // 기존 객체에는 여전히 John이 있다.
```

<br/>

[두 번째 방법] Object.assign:

[문법] Object.assign 사용:
```javascript
Object.assign(dest, [src1, src2, src3...])
```
- 첫 번째 인수 `dest`는 목표로 하는 객체이다.
- 이어지는 인수 `src1, ...m srcN`는 복사하고자 하는 객체이다.
- 객체 `src1, ..., srcN`의 프로퍼티를 `dest`에 복사한다. `dest`를 제외한 인수(객체)의 프로퍼티 전부가 첫 번째 인수(객체)로 복사된다.
- 마지막으로 `dest`를 반환한다.

[예시 코드] Object.assign 사용:
```javascript
----------------------------------------------------------
let user = { name: "John" };

let permissions1 = { canView: true };
let permissions2 = { canEdit: true };

// permissions1과 permissions2의 프로퍼티를 user로 복사
Object.assign(user, permissions1, permissions2);

console.log(user); // {name: 'John', canView: true, canEdit: true}
----------------------------------------------------------
let user = { name: "John" };

Object.assign(user, { name: "Pete" });

alert(user.name); // Pete, user = { name: "Pete" }
----------------------------------------------------------
let user = {
  name: "John",
  age: 30
};

let clone = Object.assign({}, user);
----------------------------------------------------------
```

## 9. 중첩 객체 복사
지금까지는 모든 프로퍼티가 원시값인 경우만 가정하여 설명했다.
그런데 프로퍼티는 다른 객체의 참조 값일 수도 있다. 이 경우는 어떻게 해야할까?

```javascript
let user = {
  name: "John",
  sizes: {
    height: 182,
    width: 50
  }
};

let clone = Object.assign({}, user);

alert( user.sizes === clone.sizes ); // true, 같은 객체이다.

// user와 clone는 sizes를 공유한다.
user.sizes.width++;       // 한 객체에서 프로퍼티를 변경한다.
alert(clone.sizes.width); // 51, 다른 객체에서 변경 사항을 확인한다.
```
위와 같은 코드의 방식으로 사용하면, 이상적이라고 볼 수 있을 것이다.

## 10. 가비지 컬렉션
> 참고 레퍼런스 : https://ko.javascript.info/garbage-collection
> - 지금 작성하는 이 문서에는 가비지 컬렉션 설명을 자세히 기술하지 않았기 때문에 참고 레퍼런스를 꼭 봐주자.

Javascript는 눈에 보이지 않는 곳에서 메모리 관리를 수행한다. 원시값, 객체, 함수 등 우리가 만드는 모든 것은 메모리를 차지한다. 그렇다면 더는 쓸모 없어지게 된 것들은 어떻게 처리될까?

### 10-1. 가비지 컬렉션 기준
Javascript는 도달 가능성(reachability) 이라는 개념을 사용해 메모리 관리를 수행한다.
도달 가능한(reachable) 값은 쉽게 말해 어떻게든 접근하거나 사용할 수 있는 값을 의미한다. 
도달 가능한 값은 메모리에서 삭제되지 않는다.

[예시] 도달 가능하며, 명백한 이유 없이 삭제되지 않는 값:
- 현재 함수의 지역 변수와 매개변수
- 중첩 함수의 체인에 있는 함수에서 사용되는 변수와 매개변수
- 전역 변수
- 기타 등등

이러한 값은 루트(root)라고 불린다.
루트가 참조하는 값이나 체이닝으로 루트에서 참조할 수 있는 값은 도달 가능한 값이 된다.
예를 들어, 전역 변수에 객체가 저장되어 있다고 가정해보겠다. 이 객체의 프로퍼티가 또 다른 객체를 참조하고 있다면, 프로퍼티가 참조하는 객체는 도달 가능한 값이된다. 이 객체가 참조하는 다른 모든 것들도 도달 가능하다고 여겨진다.

## 11. 메서드
```javascript
let user = {
  name: "John",
  age: 30
};

function sayBye() {
  alert("안녕히가세요.");
}

user.sayHi = function() {
  alert("안녕하세요!");
};

user.sayBye = sayBye;

user.sayHi(); // 안녕하세요!
user.sayBye(); // 안녕하가세요.
```
객체 프로퍼티에 할당된 함수를 메서드(method)라고 부른다.
위의 코드에서는 user에 할당된 sayHi가 메서드인 것이다.

### 11-1. 메서드 단축구문:
```javascript
// 아래 두 객체는 동일하게 동작한다.
user = {
  sayHi: function() {
    alert("Hello");
  }
};

// 단축 구문의 사용
user = {
  sayHi() { // "sayHi: function()"과 동일하다.
    alert("Hello");
  }
};
```
Javascript에서는 메서드 단축구문을 제공한다. 위의 코드로 설명은 갈음하겠다.

### 11-2. 메서드와 this
```javascript
let user = {
  name: "John",
  age: 30,

  /**
   * sayHi: function() {
   *   alert(this.name);
   *  }  
  */
  // 단축 구문
  sayHi() {
    alert(this.name);
  },

  // 단축구문 
  myAge() {
    alert(user.age);
  }
};

user.sayHi(); // John
user.myAge(); // 30
```
메서드 내부에서 `this` 키워드를 사용하면 객체에 접근할 수 있다.
`this`를 사용하지 않더라도, 외부 변수를 참조해 객체에 접근하는 것도 가능하다.

[에러 예제 코드] 
```javascript
let user = {
  name: "John",
  age: 30,

  sayHi() {
    alert( user.name ); // Error: Cannot read property 'name' of null
  }

};


let admin = user;
user = null; // user를 null로 덮어쓴다.

admin.sayHi(); // sayHi()가 엉뚱한 객체를 참고하면서 에러가 발생한다.
```
그런데 이렇게 외부 변수를 사용해 객체를 참조할 경우 예상치 못한 에러가 발생할 수 있다.
`user`를 복사해 다른 변수에 할당(admin = user)하고, user는 전혀 다른 값으로 덮어썼다고 가정해보겠다.
syaHi()는 원치 않는 값(null)을 참조할 것이다.

## ⭐️ 13. 자유로운 this
Javascript의 this는 다른 프로그래밍 언어의 this와 동작 방식이 다르다.
Javascript에선 모든 함수에 this를 사용할 수 있다.

```javascript
function sayHi() {
  alert( this.name );
}
```
위와 같이 코드를 작성해도 문법 에러가 발생하지 않는다.
this 값은 런타임에 결정된다. 컨텍스트에 따라 달라지며, 동일한 함수라도 다른 객체에서 호출했다면 'this’가 참조하는 값이 달라진다.

```javascript
let user = { name: "John" };
let admin = { name: "Admin" };

function sayHi() {
  alert( this.name );
}

// 별개의 객체에서 동일한 함수를 사용함
user.sayHi = sayHi;
admin.sayHi = sayHi;

// 'this'는 '점(.) 앞의' 객체를 참조하기 때문에
// this 값이 달라짐
user.sayHi(); // John  (this == user)
admin.sayHi(); // Admin  (this == admin)

admin['sayHi'](); // Admin (점과 대괄호는 동일하게 동작함)

alert(user.sayHi === admin.sayHi) // true
```
obj.f()를 호출했다면 this는 f를 호출하는 동안의 obj이다. 위 예시에선 obj가 user나 admin을 참조한다.

## ⭐️ 14. this가 없는 화살표 함수
<font color="steelblue"> 화살표 함수 </font> 는 <font color="Salmon">일반 함수와 달리 <b><u>고유한 this를 가지지 않는다.</u></b> </font>

```javascript
let user = {
  firstName: "보라",
  // 메소드 축약
  sayHi() {
    let arrow = () => alert(this.firstName);
    arrow();
  }
};

user.sayHi(); // 보라
```
별개의 this가 만들어지는 건 원하지 않고, 외부 컨텍스트에 있는 this를 이용하고 싶은 경우 화살표 함수가 유용하다.

## 14. new연산자와 생성자 함수
객체 리터럴 `{...}` 을 사용하면 객체를 쉽게 만들 수 있다.
그런데 개발을 하다 보면 유사한 객체를 여러 개 만들어야 할 때가 생기곤 한다.

### 14-1. 생성자 함수
```javascript
function User(name) {
  this.name = name;
  this.isAdmin = false;
}

let user = new User("보라");

alert(user.name); // 보라
alert(user.isAdmin); // false
```
위와 같은 코드는 재사용할 수 있는 객체 생성 코드를 구현하게 해준다.

### 14-2. 생성자와 return문
생성자 함수엔 보통 return 문이 없다. 반환해야 할 것들은 모두 this에 저장되고, this는 자동으로 반환되기 때문에 반환문을 명시적으로 써 줄 필요가 없다.

그런데, 만약 return 문이 있다면 어떤 일이 벌어질까? 아래와 같은 간단한 규칙이 적용된다.
- 객체를 return 한다면 this 대신 객체가 반환된다.
- 원시형을 return 한다면 return문이 무시된다.

[예제 코드] 객체를 return 한다면 this 대신 객체가 반환:
```javascript
function BigUser() {
  this.name = "원숭이";

  return { name: "고릴라" };  // <-- this가 아닌 새로운 객체를 반환함
}

alert( new BigUser().name );  // 고릴라
```

[예제 코드] 아무것도 return하지 않는 예시로, 원시형을 return 한다면 return문이 무시되는 규칙이 적용:
```javascript
function SmallUser() {
  this.name = "원숭이";

  return; // <-- this를 반환함
}

alert( new SmallUser().name );  // 원숭이
```

### 14-3. 생성자 내 메소드
```javascript
function User(name) {
  this.name = name;

  this.sayHi = function() {
    alert( "제 이름은 " + this.name + "입니다." );
  };
}

let bora = new User("이보라");

bora.sayHi(); // 제 이름은 이보라입니다.

/*
bora = {
   name: "이보라",
   sayHi: function() { ... }
}
*/
```
아래 예시에서 new User(name)는 프로퍼티 name과 메서드 sayHi를 가진 객체를 만들어준다.

## 15. 옵셔널 체이닝
옵셔널 체이닝(optional chaining) `?.`을 사용하면 프로퍼티가 없는 중첩 객체를 에러 없이 안전하게 접근할 수 있다.
옵셔널 체이닝은 '앞’의 평가 대상이 undefined나 null이면 평가를 멈추고 undefined를 반환한다.

이러한 평가 방식을 <font color="steelblue"> 단락 평가 </font>라고 부른다.
- `?.`는 왼쪽 평가대상에 값이 없으면 즉시 평가를 멈춘다.
- 즉, ?. 오른쪽에 있는 부가 동작은 ?.의 평가가 멈췄을 때 더는 일어나지 않는다.

```javascript
let user = {}; // 주소 정보가 없는 사용자

// user의 평가는 object이며, 내부 address는 undefiend로 평가가 되어진다.
alert(user?.address?.street); // undefined
alert(user.address.street); // TypeError: Cannot read property 'street' of undefined
```
옵셔널 체이닝의 남용은 지양해야한다. 
상황에 따라 다르지만 프로그램 논리적으로 객체가 반드시 존재해야하는 경우라고 한다면, 옵셔널 체이닝`?.`을 사용하는 것은 바람직하지 않다. 
즉, 프로그램 논리적으로 객체가 반드시 존재해야 함에도 불구하고 undefiend로 나온다면 이는 비즈니스 로직상 문제가 있다는 것을 암시한다.

### 15-1. 옵셔널 체이닝은 연산자가 아니다.
`?.`은 연산자가 아니다. 
`?.`은 함수나 대괄호와 함께 동작하는 특별한 문법 구조체(syntax construct)이다.

#### [15-1-1] `?.()`와 `?.[]`
[예시 코드] `?.()` :
```javascript
let user1 = {
  admin() {
    alert("관리자 계정입니다.");
  }
}

let user2 = {};

user1.admin?.(); // 관리자 계정입니다.
user2.admin?.();
// user2.admin();  => TypeError: user2.admin is not a function
```
두 상황 모두에서 user 객체는 존재하기 때문에 admin 프로퍼티는 .만 사용해 접근했다.

그리고 난 후 `?.()`를 사용해 admin의 존재 여부를 확인했다. 
[1] `user1`엔 `admin`이 정의되어 있기 때문에 메서드가 제대로 호출되었다.
[2] 반면 `user2`엔 `admin`이 정의되어 있지 않았음에도 메서드를 호출하면 에러 없이 평가가 멈춘다.

<br/>

[예시 코드] `?.[]` :
```javascript
let user1 = {
  firstName: "Violet"
};

let user2 = null; // user2는 권한이 없는 사용자라고 가정한다.

let key = "firstName";

alert( user1?.[key] ); // Violet
alert( user2?.[key] ); // undefined
// user2[key]; => TypeError: Cannot read properties of null (reading 'firstName')

alert( user1?.[key]?.something?.not?.existing); // undefined
```
`.`대신 대괄호 `[]`를 사용해 객체 프로퍼티에 접근하는 경우엔 `?.[]`를 사용할 수도 있다. 
`?.[]`를 사용하면 객체 존재 여부가 확실치 않은 경우에도 안전하게 프로퍼티를 읽을 수 있다.

## 16. 심볼형
```javascript
---------------------------------------
// id는 새로운 심볼이 된다.
let id = Symbol();
---------------------------------------
// 심볼 id에는 "id"라는 설명이 붙는다. (디버깅시 유리)
let id = Symbol("id");
```
Javascript는 객체 프로퍼티 키로 오직 문자형과 심볼형만을 허용한다.
'심볼(symbol)'은 유일한 식별자(unique identifier)를 만들고 싶을 때 사용한다.

<br/>

```javascript
let id1 = Symbol("id");
let id2 = Symbol("id");

alert(id1 == id2); // false
```
심볼은 유일성이 보장되는 자료형이기 때문에, 설명이 동일한 심볼을 여러 개 만들어도 각 심볼값은 다르다.

----

⚠️ <b>[예제 코드] 심볼은 문자형으로 자동 형 변환 되지 않는다:</b>
```javascript
let id = Symbol("id");
alert(id); // TypeError: Cannot convert a Symbol value to a string
```
<b><u>심볼은 문자형으로 자동 형 변환되지 않는다.</u></b>

<br/>
<br/>

[예제 코드] 심볼의 문자형 출력과 설명 출력:
```javascript
let id = Symbol("id description~~");
alert(id.toString()); // Symbol(id)가 얼럿 창에 출력됨
alert(id.description); // id description~~
```

심볼을 출력해야 하는 상황이면, `id.toString()` 메서드를 명시적으로 호출해야한다.
만약 출력해야 하는 상황이면, `id.description` 프로퍼티를 이용하여 출력할 수 있다.

### 16-1. '숨김' 프로퍼티
심볼을 이용하면 ‘숨김(hidden)’ 프로퍼티를 만들 수 있다. 
숨김 프로퍼티는 외부 코드에서 접근이 불가능하고 값도 덮어쓸 수 없는 프로퍼티이다.

[가정] 서드파티 코드에서 가지고 온 user라는 객체가 여러 개 있고, user를 이용해 어떤 작업을 해야 하는 상황이라고 가정한다.
```javascript
let user = { // 서드파티 코드에서 가져온 객체
  name: "John"
};

let id = Symbol("id");

user[id] = 1;

alert( user[id] ); // 심볼을 키로 사용해 데이터에 접근할 수 있다.
```
문자열 "id"를 키로 사용해도 되는데 Symbol("id")을 사용한 이유는 다음과 같다.
user는 서드파티 코드에서 가지고 온 객체이므로 함부로 새로운 프로퍼티를 추가할 수 없다. 
그런데 심볼은 서드파티 코드에서 접근할 수 없기 때문에, 심볼을 사용하면 서드파티 코드가 모르게 user에 식별자를 부여할 수 있다.

상황 하나를 더 가정해보겠다. 
제3의 스크립트(자바스크립트 라이브러리 등)에서 user를 식별해야 하는 상황이 벌어졌다고 가정한다. 
즉, user의 원천인 서드파티 코드, 현재 작성 중인 스크립트, 제3의 스크립트가 각자 서로의 코드도 모른 채 user를 식별해야 하는 상황이 벌어졌다.


제3의 스크립트에선 아래와 같이 Symbol("id")을 이용해 전용 식별자를 만들어 사용할 수 있다.
```javascript
let id = Symbol("id");
user[id] = "제3 스크립트 id 값";
```
심볼은 유일성이 보장되므로 우리가 만든 식별자와 제3의 스크립트에서 만든 식별자가 충돌하지 않는다. 
이름이 같더라도 말이다. 만약 심볼 대신 문자열 "id"를 사용해 식별자를 만들었다면 충돌이 발생할 가능성이 있다.
```javascript
let user = { name: "John" };

// 문자열 "id"를 사용해 식별자를 만들었다.
user.id = "스크립트 id 값";

// 만약 제3의 스크립트가 우리 스크립트와 동일하게 문자열 "id"를 이용해 식별자를 만들었다면...

user.id = "제3 스크립트 id 값"
// 🔥 의도치 않게 값이 덮어 쓰여서 우리가 만든 식별자는 무의미해진다!!!!!!!!!!
```

### 16-2. Symbols in a literal
객체 리터럴 `{...}`을 사용해 객체를 만든 경우, 대괄호를 사용해 심볼형 키를 만들어야 한다.
```javascript
let id = Symbol("id");

let user = {
  name: "John",
  [id]: 123 // "id": 123은 안됨
};
```
만약, `"id: 123"`이라고 하면, 심볼 id가 아니라 문자열 `"id"`가 키가 된다.

### 16-3. 심볼은 for…in 에서 배제된다.
```javascript
let id = Symbol("id");
let user = {
  name: "John",
  age: 30,
  [id]: 123
};

for (let key in user) alert(key); // name과 age만 출력되고, 심볼은 출력되지 않는다.

// 심볼로 직접 접근하면 잘 작동한다.
alert( "직접 접근한 값: " + user[id] );
```
`Object.keys(user)`에서도 키가 심볼인 프로퍼티는 배제된다.
'심볼형 프로퍼티 숨기기(hiding symbolic property)'라 불리는 이런 원칙 덕분에 외부 스크립트나 라이브러리는 심볼형 키를 가진 프로퍼티에 접근하지 못한다.

그런데 `Object.assign`은 키가 심볼인 프로퍼티를 배제하지 않고 객체 내 모든 프로퍼티를 복사한다.
```javascript
let id = Symbol("id");
let user = {
  [id]: 123
};

let clone = Object.assign({}, user);

alert( clone[id] ); // 123
```
뭔가 모순이 있는 것 같아 보이지만, 이는 의도적으로 설계된 것이다. 
객체를 복사하거나 병합할 때, 대개 id 같은 심볼을 포함한 프로퍼티 전부를 사용하고 싶어 할 것이라는 생각에서 이렇게 설계되었다.

### 16-4. 전역 심볼
앞서 살펴본 것처럼, 심볼은 이름이 같더라도 모두 별개로 취급된다. 
그런데 이름이 같은 심볼이 같은 개체를 가리키길 원하는 경우도 가끔 있다. 
애플리케이션 곳곳에서 심볼 "id"를 이용해 특정 프로퍼티에 접근해야 한다고 가정해 본다.

`전역 심볼 레지스트리`(global symbol registry) 는 이런 경우를 위해 만들어졌다. 
전역 심볼 레지스트리 안에 심볼을 만들고 해당 심볼에 접근하면, 이름이 같은 경우 항상 동일한 심볼을 반환한다.

이 메서드를 호출하면 이름이 key인 심볼을 반환한다. 
조건에 맞는 심볼이 레지스트리 안에 없으면 새로운 심볼 Symbol(key)을 만들고 레지스트리 안에 저장한다.
```javascript
// 전역 레지스트리에서 심볼을 읽는다.
let id = Symbol.for("id"); // 심볼이 존재하지 않으면 새로운 심볼을 만든다.

// 동일한 이름을 이용해 심볼을 다시 읽는다.(좀 더 멀리 떨어진 코드에서도 가능하다.)
let idAgain = Symbol.for("id");

// 두 심볼은 같습니다.
alert( id === idAgain ); // true
```
전역 심볼 레지스트리 안에 있는 심볼은 전역 심볼이라고 불린다. 
애플리케이션에서 광범위하게 사용해야 하는 심볼이라면 전역 심볼을 사용하자.

### 16-5. Symbol.keyFor
전역 심볼을 찾을 때 사용되는 Symbol.for(key)에 반대되는 메서드도 있다. 
Symbol.keyFor(sym)를 사용하면 이름을 얻을 수 있다.

[예시 코드]
```javascript
// 이름을 이용해 심볼을 찾음
let sym = Symbol.for("name");
let sym2 = Symbol.for("id");

// 심볼을 이용해 이름을 얻음
alert( Symbol.keyFor(sym) ); // name
alert( Symbol.keyFor(sym2) ); // id
```
Symbol.keyFor는 전역 심볼 레지스트리를 뒤져서 해당 심볼의 이름을 얻어낸다. 
검색 범위가 전역 심볼 레지스트리이기 때문에 전역 심볼이 아닌 심볼에는 사용할 수 없다. 
전역 심볼이 아닌 인자가 넘어오면 Symbol.keyFor는 undefined를 반환한다.

전역 심볼이 아닌 모든 심볼은 description 프로퍼티가 있다. 
일반 심볼에서 이름을 얻고 싶으면 description 프로퍼티를 사용하면 된다.
```javascript
let globalSymbol = Symbol.for("name");
let localSymbol = Symbol("name");

alert( Symbol.keyFor(globalSymbol) ); // name, 전역 심볼
alert( Symbol.keyFor(localSymbol) ); // undefined, 전역 심볼이 아님

alert( localSymbol.description ); // name
```

### 16-6. 시스템 심볼
'시스템 심볼(system symbol)'은 자바스크립트 내부에서 사용되는 심볼이다. 
시스템 심볼을 활용하면 객체를 미세 조정할 수 있다.
 <a target="blank" href="https://tc39.es/ecma262/#sec-well-known-symbols">  잘 알려진 심볼(well-known symbols)</a>에서 어떤 시스템 심볼이 있는지 살펴볼 수 있다.
- Symbol.hasInstance
- Symbol.isConcatSpreadable
- Symbol.iterator
- Symbol.toPrimitive
- 기타 등등

객체가 어떻게 원시형으로 변환되는지 알기 위해선 Symbol.toPrimitive에 대해 알아야 하는데, 뒤에서 설명한다.

## 17. 객체형을 원시형으로 반환하기
### 17-1. ToPrimitive
특수 객체 메서드를 사용하면 숫자형이나 문자형으로의 형 변환을 원하는 대로 조절할 수 있다.
객체 형 변환은 세 종류로 구분되는데, 'hint’라 불리는 값이 구분 기준이 된다. 
'hint’가 무엇인지는 <a target="blank" href="https://tc39.es/ecma262/#sec-toprimitive">명세서</a>에 자세히 설명되어 있는데, ‘목표로 하는 자료형’ 정도로 이해하시면 될 것 같다.

[문제 상황]
```javascript
const order = { item: "Laptop", price: 2000 };

// 1. 문자열로 출력하려 할 때 -> 쓸모없는 문자열 반환
console.log("주문 정보: " + order); // 출력: "주문 정보: [object Object]"

// 2. 숫자로 연산하려 할 때 -> NaN (Not a Number) 에러 발생
console.log(order * 2); // 출력: NaN
```
일반적인 객체를 만들고 이를 문자열이나 숫자로 사용하려 할 때, 
자바스크립트 엔진은 우리가 원하는 값을 알 수 없으므로 의미 없는 기본값을 반환한다.
이러한 상황에서 객체가 연산되거나 출력될 때 "내부의 특정 값을 기준으로 동작해라"라고 명시적으로 지시해야 할 필요성이 생긴다.

[해결 방식] Symbol.toPrimitive 도입:
```javascript
// 통화 금액을 관리하는 커스텀 객체
const currencyObj = {
  currency: "KRW",
  amount: 50000,

  // 의도: 객체가 원시값으로 변환될 때 호출될 통합 로직 정의
  [Symbol.toPrimitive](hint) {
    // 1. 문자열 컨텍스트 (예: 템플릿 리터럴 `${currencyObj}`, alert 등)
    if (hint === "string") {
      return `${this.amount.toLocaleString()} ${this.currency}`;
    }
    
    // 2. 숫자 연산 컨텍스트 (예: currencyObj * 2, Math.max() 등)
    if (hint === "number") {
      return this.amount;
    }
    
    // 3. default 컨텍스트 (예: currencyObj + 10000 처럼 문자열인지 숫자인지 모호할 때)
    // 보통 숫자 연산과 동일하게 처리하는 것이 현업의 일반적인 패턴입니다.
    return this.amount;
  }
};

// --- [사용 결과 검증] ---

// hint가 "string"으로 전달되는 상황
console.log(`현재 잔액은 ${currencyObj} 입니다.`); 
// 출력: "현재 잔액은 50,000 KRW 입니다."

// hint가 "number"로 전달되는 상황 (단순 곱셈)
console.log(currencyObj * 2); 
// 출력: 100000

// hint가 "default"로 전달되는 상황 (+ 연산자는 문자열 결합인지 숫자 더하기인지 모호함)
console.log(currencyObj + 15000); 
// 출력: 65000
```

[예제 코드] Symbol.toPrimitive 사용하기 :
```javascript
let user = {
  name: "John",
  money: 1000,

  [Symbol.toPrimitive](hint) {
    alert(`hint: ${hint}`);
    return hint == "string" ? `{name: "${this.name}"}` : this.money;
  }
};

// 데모:
alert(user); // hint: string -> {name: "John"}
alert(+user); // hint: number -> 1000
alert(user + 500); // hint: default -> 1500
```
현업에서 통화(Currency) 객체나 날짜 커스텀 객체를 만들 때, 객체 자체를 직관적으로 연산할 수 있도록 아래와 같이 구현한다.

과거(ES5 이전)에는 이러한 변환을 제어하기 위해 객체 내부에 toString()과 valueOf()라는 두 개의 구형 메서드를 섞어서 구현해야 했다. Modern Javascript는 Symbol.toPrimitive 하나만을 사용하여 변환 로직을 한 곳으로 응집시키는 것이 유지보수성과 명확성을 높이는 모범 사례(Best Practice)로 여겨진다.


### 17-1 toString()과 valuOf()
toString과 valueOf는 심볼이 생기기 이전부터 존재해 왔던 ‘평범한’ 메서드이다.
이 메서드를 이용하면 '구식’이긴 하지만 형 변환을 직접 구현할 수 있다.

```javascript
let user = {name: "John"};

alert(user); // [object Object]
alert(user.valueOf() === user); // true
```

- toString은 문자열 "[object Object]"을 반환한다.
- valueOf는 객체 자신을 반환한다.

[예제 코드] toString()과 valueOf()를 사용한 코드 :
```javascript
let user = {
  name: "John",
  money: 1000,

  // hint가 "string"인 경우
  toString() {
    return `{name: "${this.name}"}`;
  },

  // hint가 "number"나 "default"인 경우
  valueOf() {
    return this.money;
  }

};

alert(user); // toString -> {name: "John"}
alert(+user); // valueOf -> 1000
alert(user + 500); // valueOf -> 1500
```
