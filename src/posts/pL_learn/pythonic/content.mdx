# 1. 파이썬스러운 객체 생성
-   <b>User</b>라는 클래스가 있다는 가정
    | 상황         | 추천                         |
    | ---------- | -------------------------- |
    | 단순 객체 생성   | `User(...)`                |
    | 단순 데이터 객체  | `@dataclass` + `User(...)` |
    | 기본값이 있음    | 기본 인자                      |
    | 생성 규칙이 있음  | `User.create(...)`         |
    | 다른 타입에서 변환 | `User.from_xxx(...)`       |
    | 복잡한 생성 로직  | Factory 함수 / Factory 클래스   |

- 생성자를 단순히 유지한다.
- 키워드 인자와 `dataclass`, 필요하면 `classmethod` 팩토리 메서드를 사용하는 방식이 자연스럽다.

## [1-1] 기본적인 객체 생성
```python
class User:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age


user = User(name="Kim", age=30)
print(user) # <__main__.User object at 0x105d446e0>
```
객체를 생성할 때 명시적으로 파라메터를 타겟팅하여 값을 넣어주는 것이 좋다.
이는 Builder 패턴으로 객체를 만드는 방식을 명확한 명시적 파라미터 값을 줌으로써 깔끔하게 대체가능하다.

## [1-2] 값을 담는 객체라면 `@dataclass`
```python
from dataclasses import dataclass


@dataclass
class User:
    name: str
    age: int


user = User(
    name="Kim",
    age=30,
)

print(user) # User(name='Kim', age=30)
```
<b>@dataclass</b>는 \_\_init\_\_, \_\_repr\_\_, \_\_eq\_\_<sup>[파이썬의 매직 메서드](#b-1)</sup> 를 자동으로 만들어준다.
또한 일반 클래스와 똑같이 명시적 값 할당 덕분에 Builder 패턴으로 객체를 만드는 것을 깔끔하게 대체가능하다.

## [1-3] 생성 방식이 여러가지라면 `@classmethod`
```python
@dataclass
class User:
    name: str
    age: int
    created_at: datetime

    @classmethod
    def create(cls, name: str, age: int) -> "User":
        return cls(
            name=name,
            age=age,
            created_at=datetime.now(),
        )

User = User.create(name="김은철", age=30);
```
`@classmethod`는 <u>"객체(instance)"가 아니라 "클래스(class) 자체"를 첫 번째 인자로 받는 메서드</u>이다.

## [1-4] 외부 데이터에서 생성한다면 `from_XXX`
```python
@dataclass
class User:
    name: str
    age: int

    @classmethod
    def from_dict(cls, data: dict) -> "User":
        return cls(
            name=data["name"],
            age=data["age"],
        )

data = {
    "name": "Kim",
    "age": 30,
}

user = User.from_dict(data)
```

## [1-5] 무조건 create()를 만들지는 않는다
```python
@dataclass
class User:
    name: str
    age: int

    @classmethod
    def create(cls, name: str, age: int) -> "User":
        return cls(
            name=name,
            age=age,
        )

user = User(
    name="Kim",
    age=30,
)
```
특별한 생성 규칙이 없다면 create()를 만들지 않고 간결하게 작성한다.

## [1-6] 파이썬은 모든 코드를 클래스 안에 두려고 하지 않는다.
```python
@dataclass
class User:
    name: str
    age: int

def create_default_user(name: str) -> User:
    return User(
        name=name,
        age=20,
    )

user = create_default_user("Kim")
```
들여쓰기를 잘못한 것이 아니다. 의도적으로 함수가 밖에 있음을 나타낸다.

## [1-7] 변경 불가능한 객체라면 `frozen=True`
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Money:
    amount: int
    currency: str

money = Money(
    amount=10000,
    currency="KRW",
)

money.amount = 20000 # FrozenInstanceError
```

## [1-8] 검증이 필요하다면 `__post_init__`
🔥 <u>dataclass의 생성 후 검증은 __post_init__을 사용할 수 있다.</u>
```python
from dataclasses import dataclass


@dataclass
class User:
    name: str
    age: int

    def __post_init__(self):
        if not self.name:
            raise ValueError("name must not be empty")

        if self.age < 0:
            raise ValueError("age must be greater than or equal to 0")
```
이렇게 작성해두면 객체 생성부터 막을 수 있다.
<u>DDD 관점에서는 생성 시점부터 invariant를 만족시키는 객체를 만드는 것과 연결해서 이해하면 된다.</u>

### 🌱 부록
#### 1. <span id="b-1">파이썬의 매직 메서드 (던디 메서드 - Dunder Method)</span>
- 
    |메서드명 | 주 역할 | 실행되는 시점 / 조건 | 설명 | 
    |---|---|---|---|
    | \_\_init\_\_ | 객체 속성 초기화 | 객체를 만들 때 | - 객체가 생성될 때 자동으로 실행되는 생성자이다. <br/> - 객체 내부의 속성(변수)에 값을 처음 넣고 준비하는 일을 한다. |
    | \_\_repr\_\_ | 객체의 문자열 표현 | repr()호출 또는 대화형 창에 객체 입력시 | - 객체를 사람이 읽기 좋은 공식적인 문자열로 바꿔준다. <br /> - `print()`로 출력하거나 콘솔에 객체를 적었을 때 보이는 모습을 정한다. | 
    | \_\_eq\_\_ | 객체 동등 비교 (==) | obj1 == obj2 비교 연산 시 | - 두 객체가 같은지 비교하는 `==`연산자의 동작을 정한다. <br/>  - 두 객체의 값이 같을 때 True를 주도적으로 직접 정할 수 있다. |

#### <span id="b-2">2. 함수의 첫 번째 인자: `self`에 대한 개념적 설명</span>
- 
    ```python
    user = User()
    user.hello() 
    ```
    위의 코드를 실행시키면 개념적으로 <b>User.hello(user)</b>처럼 동작한다.
    즉 <b>self</b>는 <b>user === self</b>이다. 이러한 이유로 <b>self</b>는 현재 메서드를 호출한 객체이다.

    다시 이 문서를 읽을 때 <b>User.hello(user)</b>의 이해가 어려울 수 있는데 개념적으로 <u>파이썬의 클래스도 하나의 객체이다.</u>

#### <span id="b-3">3. `@classmethod`의 첫 번째 인자: cls에 대한 개념적 설명</span>
-   ```python
    class User:

    @classmethod
    def hello(cls):
        print(cls)

    print(User) # <class '__main__.User'>
    ```
    위의 코드를 실행시키면 개념적으로 <b>User.hello(User)</b>처럼 동작한다.
    즉 <b>cls</b>는 <b>User === cls</b>이다. 이러한 이유로 <b>cls</b>는 User 클래스 그 자체이다. (User 클래스 객체)
    예제 코드의 <b>\<class '\_\_main\_\_.User'\></b>의 출력이 이를 증빙한다.
        - \_\_main\_\_: 프로그램이 시작되는 최상위 실행 환경의 이름이다.

    <b>User.hello(user)</b>가 이해가 잘 안 될 수 있는데, 개념적으로 <u>파이썬의 클래스도 하나의 객체이다.</u>

#### <span id="b-6">6. `@staticmethod`: 정적 메소드를 만드는 방법 </span>
    - ```python
        from dataclasses import dataclass
        from datetime import datetime


        @dataclass
        class User:
            name: str
            age: int
            created_at: datetime

            @staticmethod
            def create(name: str, age: int) -> "User":
                return User(
                    name=name,
                    age=age,
                    created_at=datetime.now(),
                )

        user = User.create("kim", 30)
        ```

        정적 메소드 데코레이션이기 때문에 첫 번째 인자로 <b> self를 받지 않는다. </b>

#### 🔥 <span id="b-7">7. `@classmethod`는 Java의 static 메소드와 동치인가?</span>
- 결과적으로 정적패토리 메소드처럼 사용하여 객체를 만들 수 있지만 <b>현재의 물음의 답은 '아니다. 잘못된 이해다.'</b>
Python에는 Java의 static과 거의 대응되는 <b>@staticmethod</b> 데코레이션이 따로 있다.<sup> [@staticmethod: 정적 메소드를 만드는 방법](#b-6) </sup>

#### 🔥 <span id="b-8">8. `@staticmethod`를 사용하지 않고 `@classmethod`를 사용하여 팩토리 메소드처럼 만드는 이유</span>
    - ```python
      User.create("kim", 30) # ---- 개념적 표현 ----> User.create(User, "kim", 30)
      ```
      <b>cls</b>는 현재 호출한 클래스를 Python이 자동으로 넘겨주는 것이다. 
      앞서 설명한 것처럼 <b>cls</b>에는 클래스 그 자체가 들어간다. 여기서는 User 클래스가 될 것이다.
      <b>@staticmethod</b>와 <b>@classmethod</b>의 <b>return</b>이 각각 <b>User(...)</b>와 <b>cls(...)</b> 서로 다르다. 
      두 데코레이션의 호출을 하는 방식은 마치 팩토리 메소드로 객체를 만드는 것처럼 사용법은 동일하지만 상속이 들어오게 되었을 때 큰 차이가 발생한다. 

        ```python
        @dataclass
        class User:
            name: str
            age: int
            created_at: datetime

            @classmethod
            def create(cls, name: str, age: int):
                return cls(
                    name=name,
                    age=age,
                    created_at=datetime.now(),
                )


        class Admin(User):
        pass

        user = User.create("kim", 30) # -- 개념적 표현 --> User.create(User) (∴) cls == User
        admin = Admin.create("lee", 40) # -- 개념적 표현 --> Admin.create(Admin) (∴) cls == Admin

        print(type(user))   # <class '__main__.User'>
        print(type(admin))  # <class '__main__.Admin'>
        ```
        이러한 결과가 나오는 이유는 <b>cls</b>의 동작방식 때문에 있다. 이는 주석을 참고하길 바란다.
        
        [`@staticmethod`: 정적 메소드를 만드는 방법](#b-6)의 예시코드를 <b>Admin2 클래스</b>가 상속 받은 형태라고 생각해보자.
        `@staticmethod`는 User 객체를 반환하기 때문에 <b>type(Admin2.create("lee", 30))</b>는 <b>\<class '__main__.User'></b>가 나올 것이다. 그리고 <u><b>Admin2 클래스</b>에 <b>ban_user</b>라는 기능이 있다고 가정해보자. 현재 만들어진 객체로는 <b>ban_user</b> 기능을 호출하지 못한다. 왜냐하면 User 객체이기 때문이다.</u> 오류는 다음과 같을 것이다. 
            - <b> AttributeError: 'User' object has no attribute 'ban_user' </b>

다형성 관점에서도 고민해봤지만, 이 문제는 다형성과는 다른 이야기다.
다형성에서는 실제 자식 객체가 존재한 상태에서 이를 부모 타입으로도 다룰 수 있다. 하지만 @staticmethod에서 Admin.create()가 User(...)를 반환하는 경우에는 애초에 Admin 객체가 생성되지 않는다. 따라서 Admin만의 기능을 사용할 수도 없다.
