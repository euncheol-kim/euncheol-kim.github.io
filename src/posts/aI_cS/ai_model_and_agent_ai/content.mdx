## 개요
> **AI Agent는 어떤 목표를 가지는가?**

2022년 12월 1일 ChatGPT가 시장에 공개됐다. ChatGPT는 사용자의 어떤 질문에도 "이 질문은 저의 분야가 아닙니다."라는 답변을 하지 않고 사용자의 질문 의도를 파악해 가장 적절한 답을 내놓는다. 이처럼 한 분야에 갇혀있지 않고 모든 영역을 포괄하여 답변해주는 AI를 <b>범용 AI라고하며 AGI<sup> Artificial General Intelligence </sup>라고 한다.</b>

4년이 지난 현재의 AI분야에서는 Hallucination<sup> 환각: 거짓된 정보로 답변하는 것 </sup>, 편향성, 저작권 및 무단 수집 등과 같은 문제를 해결하기 위해 노력하고 있고, AGI를 넘어서 <u>"기계가 할당된 역할의 문제를 스스로 해결하기 위해 계획부터 실행, 그리고 추론을 통한 결과 도출"</u>까지의 <b>자율적 문제 해결 단계</b>로 발전하고 있다. 쉽게 말해서 <b>인간의 개입이 최소화 된 스스로 일하는 AI</b>를 말한다. 현대의 AI 에이전트가 이 목표를 지향한다.

> **AI Agent 등장 이전에 확립된 AI Model은 무엇인가?**

나는 지금까지 AI Model은 "질문자의 입력을 특정 패턴으로 이해(유사도) 및 출력한다. 더 나아가서는 이 기계가 스스로 정형화된 패턴을 만들고 이해하며 진화한다." 정도로 이해하고 있었다. 그러면, 도대체 <b>AI Agent가 무엇이며 어떤 역할을 하는가?</b> 에 대해서 이해를 할 수가 없었다. 두 개념이 매우 비슷하면서도 중복되는 역할과 책임이 있는 것 같았기 때문이다. 나는 이번 학습을 통해 AI Model과 AI Agent의 역할과 차이를 명확하게 알기를 바라고 있다.

# AI Model과 AI Agent

## 1. AI Model

<b>AI 모델</b>은 대량의 데이터를 학습하여 데이터에 존재하는 규칙과 패턴을 학습하고, 주어진 입력을 바탕으로 적절한 출력을 생성하는 계산 모델을 말한다.

예를 들어 사용자에게 다음과 같은 입력이 주어졌다고 가정해보자.

> "HTTP와 HTTPS의 차이를 설명해줘."

AI 모델은 입력된 문장과 현재 주어진 문맥(Context)을 바탕으로 어떤 내용이 이어지는 것이 적절한지를 계산하고 그에 따른 결과를 생성한다.

> Input → AI Model → Output

단순화하면 AI 모델은 위와 같은 흐름으로 동작한다. 즉, AI 모델의 핵심 역할은 <b>주어진 입력을 바탕으로 적절한 출력을 생성하는 것</b>이다.

여기서 한 가지 의문이 생길 수 있다.

> 입력에 대한 출력을 만들어내는 것 자체가 AI 모델의 목적이 아닌가?

AI 모델에도 학습 과정에서 최적화해야 하는 목적(Objective)은 존재한다. 예를 들어 LLM은 주어진 문맥을 바탕으로 다음에 등장할 Token(단어 조각)을 더 정확하게 예측하도록 학습될 수 있다.
AI 모델이 토큰을 예측하는 것이 중요한 이유는 문맥을 파악하는 법을 배우고 이를 통해 추론하며 이 결과 인간의 언어를 흉내낼 수 있기 떄문이다.

하지만 여기서 말하는 <b>학습의 목적(Objective)</b>과 사용자가 실제로 달성하고자 하는 <b>업무상의 목표(Goal)</b>는 구분할 필요가 있다.

예를 들어 사용자의 목표가 다음과 같다고 가정해보자.

> "이번 주말 서울에서 부산으로 가는 가장 저렴한 교통편을 찾아줘."

AI 모델은 이 목표를 입력받아 어떤 행동이 필요할지 설명하거나 다음 행동을 제안할 수 있다. 그러나 <b>AI 모델 자체가 검색 사이트를 확인하고, 가격을 비교하고, 결과가 충분한지 판단한 뒤 다시 검색하는 일련의 과정을 지속적으로 관리하는 것은 아니다.</b>

AI 모델의 한 번의 실행(Inference)은 기본적으로 다음과 같다.

> Input → Model → Output

즉, 모델은 현재 주어진 입력에 대해 출력을 생성한다. 이후 무엇을 해야 하는지, 이전 행동의 결과는 어떠했는지, 목표를 달성했는지 등을 지속적으로 관리하는 역할은 모델 자체의 책임이 아니다.

따라서 AI Model과 이후 설명할 AI Agent의 차이를 이해할 때는 다음과 같은 질문이 중요하다.

> <b>"사용자의 목표를 달성하기 위해 다음 행동을 결정하고, 그 행동의 결과를 관찰하면서 필요한 과정을 반복하는가?"</b>

AI Model 자체는 일반적으로 이러한 실행 흐름을 관리하지 않는다.

반면 현대 AI 시스템에서는 AI Model을 단순히 한 번 호출하는 것을 넘어, 사용자로부터 목표를 부여받고 현재 상황을 판단하여 필요한 행동을 선택하고 실행한 뒤, 그 결과를 다시 관찰하면서 다음 행동을 결정하는 구조가 활용되고 있다.

이를 단순화하면 다음과 같다.

> Goal → 판단 및 계획 → 행동 → 결과 관찰 → 다음 행동 결정 → ... → Goal 달성

이처럼 <b>AI Model을 활용하여 특정 목표를 달성하기 위해 필요한 행동을 결정하고 실행하며, 그 결과에 따라 다음 행동을 반복적으로 수행하는 시스템</b>을 일반적으로 <b>AI Agent</b>라고 한다.

따라서 두 개념을 가장 단순하게 구분하면 다음과 같이 볼 수 있다.

> <b>AI Model은 "주어진 입력에 대해 무엇을 출력할 것인가?"를 다루고, AI Agent는 "주어진 목표를 달성하기 위해 다음에 무엇을 할 것인가?"를 다룬다.</b>

## 2. AI Agent

<b>AI Agent</b>는 사용자가 부여한 목표(Goal)를 달성하기 위해 현재 상황을 판단하고, 필요한 행동을 결정하고 실행하며, 그 결과를 다시 확인하는 과정을 반복하는 시스템을 말한다.

앞서 AI Model을 다음과 같이 단순화했다.

> Input → AI Model → Output

AI Agent는 이보다 조금 더 복잡한 흐름을 가진다.

> Goal → 상황 판단 → 행동 결정 → 행동 실행 → 결과 관찰 → 다음 행동 결정 → ... → Goal 달성

즉, AI Agent의 핵심은 단순히 사용자의 입력에 대한 답변을 생성하는 것이 아니라 <b>사용자가 원하는 목표를 달성하기 위해 무엇을 해야 하는지 판단하고 실제 행동으로 이어가는 것</b>에 있다.

예를 들어 사용자가 다음과 같이 요청했다고 가정해보자.

> "이번 주말 서울에서 부산으로 가는 가장 저렴한 교통편을 찾아줘."

단순한 AI Model이라면 학습한 지식과 현재 입력을 바탕으로 다음과 같은 답변을 생성할 수 있다.

> "서울에서 부산으로 이동할 때는 KTX, 고속버스, 항공편 등을 비교해보는 것이 좋습니다."

이는 사용자의 질문에 적절한 답변이지만, 사용자의 실제 목표인 <b>"가장 저렴한 교통편을 찾는 것"</b>이 달성된 것은 아니다.

반면 AI Agent는 목표를 달성하기 위해 필요한 작업을 단계적으로 수행할 수 있다.

예를 들어 다음과 같은 과정이 이루어질 수 있다.

1. 사용자가 원하는 출발일과 도착일을 확인한다.
2. KTX 가격을 검색한다.
3. 고속버스 가격을 검색한다.
4. 항공편 가격을 검색한다.
5. 검색한 결과를 비교한다.
6. 조건에 맞는 가장 저렴한 교통편을 선택한다.
7. 최종 결과를 사용자에게 전달한다.

이 과정에서 중요한 점은 Agent가 단순히 한 번의 답변을 생성하고 종료되는 것이 아니라는 것이다.

Agent는 <b>현재까지 어떤 작업을 수행했는지 확인하고, 목표를 달성하기 위해 다음에 어떤 행동이 필요한지를 판단한다.</b>

이를 조금 더 일반화하면 다음과 같은 구조로 표현할 수 있다.

> Observe → Reason / Plan → Act → Observe → ...

각 단계는 다음과 같은 의미를 가진다.

### Observe

현재 상황과 이전 행동의 결과를 확인하는 단계다.

예를 들어 항공편 검색 API를 호출했다면 Agent는 API를 통해 반환된 가격, 출발 시간, 좌석 등의 정보를 확인할 수 있다.

### Reason / Plan

현재 상태와 목표를 바탕으로 다음에 어떤 행동이 필요한지 판단하는 단계다.

예를 들어 KTX 가격만 확인한 상태라면 아직 가장 저렴한 교통편을 결정할 수 없기 때문에 다음으로 고속버스나 항공편을 조회해야 한다고 판단할 수 있다.

### Act

실제로 필요한 행동을 수행하는 단계다.

행동에는 단순한 텍스트 생성뿐만 아니라 다양한 외부 시스템의 사용이 포함될 수 있다.

예를 들면 다음과 같다.

* Web 검색
* 외부 API 호출
* Database 조회
* 파일 읽기 및 작성
* Email 전송
* Calendar 일정 등록
* 프로그램 실행

이처럼 Agent가 외부 환경과 상호작용하기 위해 사용하는 기능을 일반적으로 <b>Tool</b>이라고 한다.

즉, AI Agent는 AI Model이 생성한 텍스트만으로 모든 작업을 수행하는 것이 아니라 필요한 경우 외부 Tool을 사용하여 실제 데이터를 조회하거나 행동을 수행할 수 있다.

---

### AI Model은 Agent의 판단을 돕는 핵심 구성 요소다

AI Agent와 AI Model은 서로 완전히 독립적인 개념이라기보다, 일반적으로 <b>AI Agent 내부에서 AI Model이 핵심적인 판단 엔진 역할을 수행하는 관계</b>로 이해하는 것이 좋다.

단순화하면 다음과 같이 표현할 수 있다.

> AI Agent
> ├─ Goal
> ├─ AI Model
> ├─ Tools
> ├─ Memory / State
> └─ Execution Loop

여기서 AI Model은 현재 상황을 분석하거나 다음 행동을 결정하는 데 사용될 수 있다.

하지만 실제 API를 호출하거나, 파일을 작성하거나, 이전 작업 결과를 저장하고 관리하거나, 작업을 언제 종료할지를 결정하는 전체 실행 구조는 AI Model 자체가 아니라 <b>Agent System</b>이 담당한다.

따라서 다음과 같이 이해할 수 있다.

> <b>AI Model은 Agent의 두뇌와 같은 역할을 할 수 있지만, AI Agent는 Model뿐만 아니라 목표, 상태, Tool, 실행 흐름 등을 포함하는 하나의 시스템이다.</b>

---

### Tool

<b>Tool</b>은 Agent가 외부 환경과 상호작용하기 위해 사용할 수 있는 기능이다.

AI Model 자체는 일반적으로 자신이 학습한 정보와 현재 Context를 바탕으로 출력을 생성한다.

따라서 실시간 정보가 필요한 경우에는 한계가 발생한다.

예를 들어 다음과 같은 요청을 생각해볼 수 있다.

> "현재 서울 날씨를 알려줘."

AI Model의 학습 데이터만으로는 현재 시점의 정확한 날씨를 알 수 없다.

이때 Agent는 Weather API와 같은 Tool을 사용할 수 있다.

> User
> ↓
> Agent
> ↓
> Weather API 호출
> ↓
> 현재 날씨 데이터 반환
> ↓
> AI Model이 결과 해석
> ↓
> User에게 결과 전달

따라서 Tool은 Agent가 AI Model 내부의 지식만으로 해결할 수 없는 작업을 외부 시스템을 통해 수행할 수 있도록 만들어준다.

### Memory와 State

Agent가 여러 단계를 수행하려면 이전에 어떤 작업을 수행했고 어떤 결과를 얻었는지를 알고 있어야 한다.

이를 위해 Agent에서는 <b>State</b> 또는 <b>Memory</b>라는 개념이 사용된다.

예를 들어 교통편을 비교하는 Agent가 있다고 가정해보자.

> KTX 검색 결과: 59,800원
> 고속버스 검색 결과: 39,700원
> 항공편 검색 결과: 아직 조회하지 않음

Agent는 이러한 상태를 기억하고 있어야 다음과 같이 판단할 수 있다.

> "항공편 가격을 아직 확인하지 않았으므로 항공편을 검색해야 한다."

만약 이전 행동의 결과를 기억하지 못한다면 매번 처음부터 작업을 시작해야 하기 때문에 목표를 효과적으로 달성하기 어렵다.

따라서 Agent의 State는 <b>현재 목표를 달성하기 위해 지금까지 무엇을 알고 있고 무엇을 수행했는지를 관리하는 정보</b>라고 볼 수 있다.

다만 Memory와 State는 완전히 동일한 개념으로 사용되지는 않는다.

일반적으로 State는 현재 작업 흐름에서 필요한 상태를 의미하고, Memory는 이전 대화나 과거 작업과 같이 더 장기적으로 유지되는 정보를 의미하는 경우가 많다.

---

### Agent Loop

AI Agent를 이해할 때 가장 중요한 개념 중 하나가 <b>Agent Loop</b>다.

Agent는 목표를 받으면 한 번의 Model 호출만으로 모든 문제를 해결하려 하지 않는다.

현재 상태를 확인하고 필요한 행동을 수행한 뒤 그 결과를 다시 입력으로 사용하여 다음 행동을 결정한다.

예를 들어 다음과 같은 흐름이 만들어질 수 있다.

> Goal
> ↓
> 현재 State 확인
> ↓
> AI Model에게 다음 행동 판단 요청
> ↓
> Tool 실행
> ↓
> Tool 실행 결과를 State에 반영
> ↓
> 목표 달성 여부 확인
> ↓
> 목표를 달성하지 못했다면 다시 판단
> ↓
> 목표 달성 시 종료

이를 의사 코드로 단순화하면 다음과 같이 생각할 수 있다.

```text
while (goal is not completed) {
    observe current state

    decide next action

    execute action

    observe result

    update state
}
```

하지만 단순히 반복문이 존재한다고 해서 Agent가 되는 것은 아니다.

Agent의 핵심은 <b>목표와 현재 상태를 기반으로 다음 행동을 결정하고, 행동의 결과에 따라 이후 행동을 변경할 수 있다는 것</b>이다.

### AI Agent는 반드시 완전히 자율적일 필요는 없다

AI Agent라는 표현 때문에 사람이 아무런 개입을 하지 않아도 모든 작업을 스스로 수행하는 완전히 자율적인 시스템을 떠올리기 쉽다.

하지만 실제 Agent는 다양한 수준의 자율성을 가질 수 있다.

예를 들어 다음과 같은 구조도 충분히 Agent가 될 수 있다.

> Agent가 작업 계획 생성
> ↓
> 사용자에게 승인 요청
> ↓
> 승인된 경우에만 Email 전송

특히 결제, 이메일 전송, 데이터 삭제처럼 실제 시스템에 영향을 주는 행동에서는 사용자의 승인을 요구하는 방식이 많이 사용된다.

따라서 Agent의 핵심은 <b>완전한 자율성</b>이 아니라 <b>목표를 중심으로 여러 행동을 선택하고 실행할 수 있는 구조</b>에 있다.

### AI Model과 AI Agent의 차이

두 개념을 정리하면 다음과 같다.

| 구분          | AI Model             | AI Agent                    |
| ----------- | -------------------- | --------------------------- |
| 핵심 역할       | 입력에 대한 출력 생성         | 목표 달성을 위한 행동 수행             |
| 중심 개념       | Input / Output       | Goal / Action               |
| 상태 관리       | 일반적으로 Model 외부에서 관리  | 작업 수행을 위해 State를 관리         |
| Tool 사용     | Model 자체가 직접 실행하지 않음 | 필요에 따라 Tool 실행              |
| 반복 수행       | 자체적으로 실행 흐름을 관리하지 않음 | 목표 달성을 위해 행동을 반복            |
| 외부 환경과 상호작용 | 제한적                  | API, DB, Web 등의 Tool을 통해 가능 |
| 종료 조건       | 출력 생성                | Goal 달성 또는 종료 조건 충족         |

따라서 AI Agent를 단순히 <b>"더 똑똑한 AI Model"</b>이라고 이해해서는 안 된다.

AI Agent는 AI Model이라는 하나의 구성 요소를 이용하여 <b>목표를 달성하기 위한 실행 구조를 만든 시스템</b>에 가깝다.

> <b>AI Model은 판단과 생성을 담당하고, AI Agent는 그 판단을 이용하여 목표를 향해 행동한다.</b>

결국 두 개념의 관계는 다음과 같이 정리할 수 있다.

> AI Model
> = Input을 받아 Output을 생성하는 모델

> AI Agent
> = AI Model을 포함한 여러 구성 요소를 이용하여 Goal을 달성하기 위한 행동을 반복적으로 수행하는 시스템

이 차이를 이해하고 나면 이후 등장하는 <b>Tool Calling, Function Calling, Memory, Planning, Workflow, Multi-Agent</b> 등의 개념 역시 AI Agent를 구성하기 위한 각각의 요소로 바라볼 수 있다.
